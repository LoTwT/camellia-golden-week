# camellia-golden-week

《绝区零》「沙罗黄金周」（Camellia Golden Week）空洞电视格子玩法的单人本地复刻。保留探索、机关、格子内挑战与四区联动，移除剧情、空洞外流程和动作战斗。

R1 已完成三个信号组装盗取终端、四组推车捕获、持续堆积的三档杀毒、重新测绘的 A / B / D 机关和专用界面。默认 M5 包含中心、A–D 四区、回访和中央仓库，保持 26 个唯一奖励、130 单位物资。首次 R1 交付的完整 `pnpm run verify` 通过，682 项原生测试零失败；63 项验收为 **62 项通过、V06 断网不再要求**，逐项证据见[R1 验收结果](docs/verification/r1-acceptance-results.md)。

2026-09-13 补修了侧路进入房间后的保存、JSON 对象键重排导入和旧档迁移说明，当前 787 项原生测试通过，实际验证与边界见[PR 存档审查修复](docs/verification/pr-save-review-fixes.md)。下列 Release ZIP 保留首次 R1 交付，不含后续修复；最新版本请使用当前 PR 源码构建。

本机独立 Chrome 已正常键鼠完成跳过计分挑战到仓库、M5 的 130 全收集、三个盗取与四组捕获，以及 M1–M3 独立全收集、升级续玩、旧档完成访问与新版练习链。视口、性能、菜单和故障恢复均有本轮证据，历史通过数未继承。可直接打开[固定本地入口](http://localhost:5174)，或下载[R1 静态 ZIP](https://github.com/LoTwT/camellia-golden-week/releases/download/v0.5.0-r1/camellia-golden-week-r1-dist.zip)；[静态交付记录](docs/verification/release-candidate.md)给出校验值与验证方法，[PR #1](https://github.com/LoTwT/camellia-golden-week/pull/1)用于审阅，不合并 main。

## 安装与运行

开发与验收使用 Node **24.18.0**、pnpm **11.25.0**；版本约束见 `.node-version` 和 `package.json`，依赖版本由 `pnpm-lock.yaml` 固定，安装设置见 `pnpm-workspace.yaml`。尚未安装 pnpm 时，按[官方安装说明](https://pnpm.io/installation#installing-a-specific-version)安装指定版本。在仓库根目录运行：

```sh
pnpm install --frozen-lockfile
pnpm run dev --host localhost --port 5174 --strictPort
```

打开 [localhost:5174](http://localhost:5174)。成品构建按以下命令运行；先关闭 dev，避免占用同一端口。

```sh
pnpm run build
pnpm run preview --host localhost --port 5174 --strictPort
```

`dist/` 是静态构建，运行所需图片、字体、声音与内容均随包提供。使用本地 HTTP 服务，不能直接双击 `index.html`；固定入口为 `http://localhost:5174`，端口占用时命令报错。首次安装依赖需要访问 npm 注册表；游戏没有后端、账号或第三方运行服务。离线运行未实测通过，也不作为本次交付保证。

使用支持 WebGL2 的桌面浏览器。完整存档会话需要可用的浏览器本地存储与 Web Locks；不支持时可主动选择临时游玩并导出。建议窗口至少为 1366×768；小于 1024×640 会提示扩大窗口，仍可使用菜单和导出。当前浏览器与设备的实际覆盖以验收记录为准，玩家无需安装测试工具或浏览器插件。

## 操作与进度

| 操作           | 键盘 / 鼠标                                                                       |
| -------------- | --------------------------------------------------------------------------------- |
| 移动           | WASD / 方向键；点击相邻格                                                         |
| 交互 / 增幅    | F / R；底部同名按钮                                                               |
| 区域图 / 暂停  | M / Esc                                                                           |
| 静态机关       | Z 撤销；底部重置或返回入口                                                        |
| 防火墙         | 跟随拍点按方向或点击不同格，每拍最多计一次                                        |
| 杀毒           | 点击已出现目标，或方向移动 / F 清除当前位置目标                                   |
| 数据盗取       | 球持续滑行至阻挡或同色基站；组合体逐格推入匹配接口；斜纹缓冲区只允许玩家进入      |
| 推车捕获       | 推车封住逃路，再靠近追赶邦布；后三组在对应盗取完成后可进入                        |
| 幽灵与灯       | 方向移动避开幽灵，走到灯所在格点亮灯                                              |
| 已完成静态房间 | 自由走过完成布局；F 开始独立练习，不改变首次结果                                  |
| 菜单           | 方向键或 W/S 循环选择，Enter / Space 确认；Esc 逐级返回；Tab / Shift+Tab 切换控件 |

探索时点击远处只会沿已访问的安全格逐步行走。隐藏路线、机关与未领取物资不能靠自动寻路跳过。键盘移动仅在棋盘获得焦点时生效。菜单方向键或 W/S 按显示顺序循环选择；滑块、下拉框和文本框保留原生按键，用 Tab 离开控件。Esc 回到上一级并恢复原选项，从暂停菜单再按 Esc 继续游戏。

防火墙使用中央 5×4 格和四块 COMBO 大屏：跟随音乐或画面周围白光移动，也可看底部文字。“现在移动”时按一次方向键，出现 PERFECT /“本拍命中”后等待下一拍；鼠标也可点不同格。长按不会自动跟拍。普通错拍减 1，触碰移动警报减 5；按拍朝箭头方向迎向警报可完美闪避，单纯踩中拍点不保证免伤。受击不清空最高 Combo，也不扣物资；减少闪烁关闭白光、亮暗变化和受击红晕，保留文字。屏幕边缘的粗箭头指向警报来处，虚线深底表示预告，实线浅底表示活动警报；交汇格会同时显示多个来向。规则来源及重建边界见[S12](docs/references/firewall-hazards.md)，计分验证见[警报修复记录](docs/verification/firewall-hazards.md)，显示与菜单验证见[本轮修复](docs/verification/controls-readability.md)。

杀毒使用 5×4 棋盘和四块波形屏。蓝色 +1、紫色 +2；目标持续积累，第 10 个普通目标出现即失败。星目标清除当前蓝紫目标；不同颜色同时使用图形和 1 / 2 / ★ 标记。四组捕获是否全部体验与 130 物资收集分别记录，不增加主线或领奖前置。

菜单、失焦、切换标签页或明显卡顿会冻结实时挑战及配乐；回到游戏后主动继续，3 秒恢复倒数不计入挑战时间。场景连接期间等待棋盘就绪后再操作。“菜单 → 声音与显示”提供音量、静音、减少闪烁、减少动态效果、画质和 0.75–1.5 倍棋盘缩放；局部机关会限制实际放大倍数以保持整盘可见，防火墙固定完整电视墙取景。声音未启用时可点击“启用声音”重试，无声状态不影响规则和成绩。防火墙三首随包配乐为 110 BPM 原创替代曲，原曲名称、实测和使用差异见 [S11](docs/references/firewall-audio.md)。

主路径终端开放下一地区，D 四权限开放 A / B 回访；四区必需数据各达到 100 后开放中央仓库。防火墙与杀毒成绩不阻挡主线完成。中央仓库结算后可自由回访补齐物资。

## 存档与恢复

稳定行动自动保存到两个交替写入的槽，写入后回读确认；顶部显示当前保存状态。启动时选择“继续游戏”。双槽保留最近的成功快照，不是无限历史记录；需要长期保留的进度请自行导出。

R1 使用规则集 v4；防火墙自身保持 v3，杀毒采用 v4。成绩按各挑战的规则版本保留，旧 v3 防火墙最高分继续有效，旧杀毒分数保留为历史记录。旧版 90 Combo 存档仍可导入，不能直接与当前 82 拍成绩比较。未完成实时挑战回到安全入口重新开始。

“菜单 → 进度与存档”提供导出、导入、重试保存和新游戏。导出提供 JSON 文件下载，同时显示可完整复制的文本。导入文件上限为 1 MiB，先校验版本、内容和进度，再显示预览；确认且写入成功后才替换当前游戏。校验或写入失败保留原进度。开始新游戏也需明确确认，可先导出旧进度。

“重新读取本地进度…”可先导出当前内存进度，确认后才重新载入页面，未保存变化不会自动写入；取消则返回存档菜单。迁移备份或保存失败会显示“进度升级未保存”或“备份恢复未保存”，可重试或导出原始槽。

页面离开后再返回，会重新取得会话并读取本地进度。若进度正由另一窗口使用，只能导出原始槽；存在离开前的内存副本时会单独标明来源和原代数，不能继续该副本或覆盖另一窗口的进度。关闭原窗口后重试，再选择继续最新本地进度。

存档属于当前浏览器的 `http://localhost:5174`。更换浏览器、协议、主机或端口需使用导出 / 导入；`localhost` 与 `127.0.0.1` 是不同存储来源。同一来源只有一个可写窗口，第二个窗口提供只读导出和“重试获取会话”；关闭原窗口后再重试。

分期升级保留已完成目标、已领取奖励、成绩及已支持的房间状态，并更新当前内容分母：M1 为 26、M2 为 51、M3 为 81、M4 / M5 为 130。升级前备份原槽并回读确认。当前存档结构为 schema 3；旧 schema 1 / 2 和 v1 / v2 / v3 规则均有显式迁移路径，M4 → M5 不增加奖励或重新要求完成仓库。旧机关完成布局按来源版本验证并归档，保留永久通行；无法兼容的活动尝试和回访返回明确安全入口。没有当前完成布局时可按 F 重新体验，实际新版练习首成才补存当前首份布局，重复练习不覆盖它或旧归档。当前静态机关刷新恢复占格与布局、清空撤销历史；记忆迷宫观察态恢复时重新观察，活动态仍隐藏答案。实时挑战中途刷新或导入会返回安全入口重新开始本局，不恢复中途分数或计时。

恢复入口按实际问题提供操作：

- 显示“未保存，可导出”：内存进度仍可继续，使用“重试保存”或导出当前进度；临时游玩不会写入原存档，关闭页面前需导出才能保留。
- 最新槽损坏且另一槽有效：可先导出原始槽，再选择“使用备份继续”。两槽都损坏、版本过新或发生冲突时保留原文，不会自动覆盖为新游戏；按界面重新读取、导出或使用兼容版本处理。
- 图形丢失：游戏暂停并尝试重建；若显示“图形暂时不可用”，可重试图形或导出进度。声音失败仍可无声继续。

## 工程检查

```sh
pnpm run lint
pnpm run format:check
pnpm run typecheck
pnpm run validate:architecture
pnpm run validate:content
pnpm test
pnpm run verify
```

核心为 Vite、TypeScript、Three.js，界面为原生 DOM；权威状态与规则是独立纯 TypeScript 层。Oxlint 检查代码，Oxfmt 检查格式，规则测试使用 Node 原生测试运行器，递归发现 `tests/` 中的 `.test.ts`，没有实际执行的用例时失败。架构检查拒绝核心层的反向引用与浏览器 API；内容校验先检查原始地图，再按 profile 裁剪，并验证必需的主路径 / 全收集见证。

`pnpm run build` 包含只读 lint、格式、类型、架构与内容检查。交付前使用 `pnpm run verify` 串联规则测试、完整构建、实际 `dist/` 资源检查和 Chrome 浏览器回归。浏览器验证需要本机已安装 Google Chrome，使用锁定的 Playwright 开发依赖启动独立 context 和临时端口，不读取日常 Chrome 进度、不占用 5174；结果写入 ignored `test-results/r1/pipeline/`。玩家不需要这些测试工具。流水线包含五个生产分期产物、正常键鼠恢复、防火墙和输入回归，以及 R1 独立观测构建的完整收集路线；63 项覆盖与故障注入边界见[R1 验收映射](docs/verification/r1-acceptance-results.md)。

单独运行 `pnpm run test:browser` 可复验五个分期的静态包和本轮浏览器回归；`pnpm run test:browser --review-only` 仅用于定位修复相关用例，不能替代正式完整验证。分期构建使用 `pnpm run build --mode m1` 至 `m5`，默认 production 为 M5；未知模式明确报错。原始验收证据与已批准规格不由 formatter 重写，新增实现、脚本、测试和维护文档接受 Oxfmt 检查。

包管理已按用户要求从 npm 迁移至 pnpm，旧 npm 命令日志保留历史含义。锁文件导入、依赖等价与本轮安装 / 检查 / 构建结果见[pnpm 迁移记录](docs/verification/pnpm-migration.md)。
