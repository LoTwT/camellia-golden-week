# camellia-golden-week

《绝区零》「沙罗黄金周」（Camellia Golden Week）空洞电视格子玩法的单人本地复刻。保留探索、机关、格子内挑战与四区联动，移除剧情、空洞外流程和动作战斗。

已按用户批准的 bfb924b 规格完成连续实施。**M1–M5 已完成当前约定范围的实现与验收。** 默认构建为 M5，包含中心与 A–D 四区、全部静态机关和实时挑战、A / B 回访、中央仓库、26 个唯一奖励及 130 单位物资。正常键鼠新档从中心到仓库、全收集、分期升级续玩、导出与刷新恢复均有实际证据。

当前交付状态见[实施进度](docs/verification/implementation-progress.md)和[验收记录](docs/verification/acceptance-results.md)。按用户本轮确认，仅以本机 Chrome 验收，性能达到原预算即通过，断网游玩不再作为发布门槛。**63 个原始用例中 62 项通过、V06 不再要求**；其他设备与 Safari / Edge 的未验证、历史失败保留，具体依据见[范围调整](docs/verification/acceptance-scope-2026-09-11.md)。

[M5 静态交付包](docs/verification/release-candidate.md)提供 ZIP、校验值与构建日志；后续[消融 Review 修复](docs/verification/review-fixes.md)记录异常存档、音频并发及新增回归检查。Chrome 原交付正式包正常续玩与刷新保持 130/130；真实历史返回与双标签验证了旧内存不能覆盖新存档。M1–M5 已按里程碑提交并推送至 `codex/full-implementation`，[PR #1](https://github.com/LoTwT/camellia-golden-week/pull/1) 已创建，供审阅；main 尚未合并。

项目文档统一从 [文档索引](docs/index.md) 进入，按任务查阅主规格、玩法、内容数据、工程、验收与来源记录。

地图和判定为规格约定的固定重建；未经证实的逐格、像素与时序不宣称原版一致。实际资源、许可、校验值与补制差异见[美术实施记录](docs/references/art-implementation.md)，最终代表画面见[六类视觉对照](docs/references/visual-comparison-m5.md)。

## 安装与运行

开发与验收使用 Node **24.18.0**、pnpm **11.25.0**；版本约束见 `.node-version` 和 `package.json`，依赖版本由 `pnpm-lock.yaml` 固定，安装设置见 `pnpm-workspace.yaml`。尚未安装 pnpm 时，按[官方安装说明](https://pnpm.io/installation#installing-a-specific-version)安装指定版本。在仓库根目录运行：

```sh
pnpm install --frozen-lockfile
pnpm run dev --host localhost --port 5174 --strictPort
```

打开 [localhost:5174](http://localhost:5174)。成品构建按以下命令运行；先关闭 dev，避免占用同一端口。

```sh
pnpm run build
pnpm run preview --host localhost --port 5174 --strictPort
```

`dist/` 是静态构建，运行所需图片、字体、声音与内容均随包提供。使用本地 HTTP 服务，不能直接双击 `index.html`；固定入口为 `http://localhost:5174`，端口占用时命令报错。首次安装依赖需要访问 npm 注册表；游戏没有后端、账号或第三方运行服务。离线运行未实测通过，也不作为本次交付保证。

使用支持 WebGL2 的桌面浏览器。完整存档会话需要可用的浏览器本地存储与 Web Locks；不支持时可主动选择临时游玩并导出。建议窗口至少为 1366×768；小于 1024×640 会提示扩大窗口，仍可使用菜单和导出。当前浏览器与设备的实际覆盖以验收记录为准，玩家无需安装测试工具或浏览器插件。

## 操作与进度

| 操作           | 键盘 / 鼠标                                            |
| -------------- | ------------------------------------------------------ |
| 移动           | WASD / 方向键；点击相邻格                              |
| 交互 / 增幅    | F / R；底部同名按钮                                    |
| 区域图 / 暂停  | M / Esc                                                |
| 静态机关       | Z 撤销；底部重置或返回入口                             |
| 防火墙         | 跟随拍点按方向或点击不同格，每拍最多计一次             |
| 杀毒           | 点击已出现目标，或方向移动 / F 清除当前位置目标        |
| 幽灵与灯       | 方向移动避开幽灵，走到灯所在格点亮灯                   |
| 已完成静态房间 | 自由走过完成布局；F 开始独立练习，不改变首次结果       |
| 菜单           | Tab / Shift+Tab 切换焦点，Enter / Space 确认；Esc 返回 |

探索时点击远处只会沿已访问的安全格逐步行走。隐藏路线、机关与未领取物资不能靠自动寻路跳过。键盘移动仅在棋盘获得焦点时生效，菜单按钮可用 Tab 操作。防火墙使用中央 5×4 格和四块 COMBO 大屏：跟随音乐或画面周围白光移动，也可看底部文字。“现在移动”时按一次方向键，出现 PERFECT /“本拍命中”后等待下一拍；鼠标也可点不同格。长按不会自动跟拍。减少闪烁关闭白光和亮暗变化，静音或减少动态时仍显示文字提示，见[防火墙还原记录](docs/verification/firewall-restoration.md)。

菜单、失焦、切换标签页或明显卡顿会冻结实时挑战及配乐；回到游戏后主动继续，3 秒恢复倒数不计入挑战时间。场景连接期间等待棋盘就绪后再操作。“菜单 → 声音与显示”提供音量、静音、减少闪烁、减少动态效果、画质和 0.75–1.5 倍棋盘缩放；局部机关会限制实际放大倍数以保持整盘可见，防火墙固定完整电视墙取景。声音未启用时可点击“启用声音”重试，无声状态不影响规则和成绩。防火墙三首随包配乐为 110 BPM 原创替代曲，原曲名称、实测和使用差异见 [S11](docs/references/firewall-audio.md)。

主路径终端开放下一地区，D 四权限开放 A / B 回访；四区必需数据各达到 100 后开放中央仓库。防火墙与杀毒成绩不阻挡主线完成。中央仓库结算后可自由回访补齐物资。

## 存档与恢复

稳定行动自动保存到两个交替写入的槽，写入后回读确认；顶部显示当前保存状态。启动时选择“继续游戏”。双槽保留最近的成功快照，不是无限历史记录；需要长期保留的进度请自行导出。

防火墙 v2 会把原规则成绩归档，已领取物资、已完成目标和主线进度保留；未完成实时挑战重新开始本局。旧版 90 Combo 存档仍可导入，不能直接与新版 82 拍成绩比较。迁移前保护旧槽，失败时可导出原文。

“菜单 → 进度与存档”提供导出、导入、重试保存和新游戏。导出提供 JSON 文件下载，同时显示可完整复制的文本。导入文件上限为 1 MiB，先校验版本、内容和进度，再显示预览；确认且写入成功后才替换当前游戏。校验或写入失败保留原进度。开始新游戏也需明确确认，可先导出旧进度。

“重新读取本地进度…”可先导出当前内存进度，确认后才重新载入页面，未保存变化不会自动写入；取消则返回存档菜单。迁移备份或保存失败会显示“进度升级未保存”或“备份恢复未保存”，可重试或导出原始槽。

页面离开后再返回，会重新取得会话并读取本地进度。若进度正由另一窗口使用，只能导出原始槽；存在离开前的内存副本时会单独标明来源和原代数，不能继续该副本或覆盖另一窗口的进度。关闭原窗口后重试，再选择继续最新本地进度。

存档属于当前浏览器的 `http://localhost:5174`。更换浏览器、协议、主机或端口需使用导出 / 导入；`localhost` 与 `127.0.0.1` 是不同存储来源。同一来源只有一个可写窗口，第二个窗口提供只读导出和“重试获取会话”；关闭原窗口后再重试。

分期升级保留已完成目标、已领取奖励、成绩及已支持的房间状态，并更新当前内容分母：M1 为 26、M2 为 51、M3 为 81、M4 / M5 为 130。升级前备份原槽并回读确认。当前存档结构为 schema 2；M1 / M2 的旧 schema 1 有显式迁移路径，M4 → M5 不增加奖励或重新要求完成仓库。静态机关恢复当前占格与布局，撤销历史清空；记忆迷宫观察态恢复时重新观察，活动态仍隐藏答案。已完成房保留首次成功布局。实时挑战中途刷新或导入会返回安全入口重新开始本局，不恢复中途分数或计时。

恢复入口按实际问题提供操作：

- 显示“未保存，可导出”：内存进度仍可继续，使用“重试保存”或导出当前进度；临时游玩不会写入原存档，关闭页面前需导出才能保留。
- 最新槽损坏且另一槽有效：可先导出原始槽，再选择“使用备份继续”。两槽都损坏、版本过新或发生冲突时保留原文，不会自动覆盖为新游戏；按界面重新读取、导出或使用兼容版本处理。
- 图形丢失：游戏暂停并尝试重建；若显示“图形暂时不可用”，可重试图形或导出进度。声音失败仍可无声继续。

## 工程检查

```sh
pnpm run lint
pnpm run format:check
pnpm run typecheck
pnpm run validate:architecture
pnpm run validate:content
pnpm test
pnpm run verify
```

核心为 Vite、TypeScript、Three.js，界面为原生 DOM；权威状态与规则是独立纯 TypeScript 层。Oxlint 检查代码，Oxfmt 检查格式，规则测试使用 Node 原生测试运行器，递归发现 `tests/` 中的 `.test.ts`，没有实际执行的用例时失败。架构检查拒绝核心层的反向引用与浏览器 API；内容校验先检查原始地图，再按 profile 裁剪，并验证必需的主路径 / 全收集见证。

`pnpm run build` 包含只读 lint、格式、类型、架构与内容检查。交付前使用 `pnpm run verify` 串联规则测试、完整构建、实际 `dist/` 资源检查和 Chrome 浏览器回归。浏览器验证需要本机已安装 Google Chrome，使用锁定的 Playwright 开发依赖启动独立 context 和临时端口，不读取日常 Chrome 进度、不占用 5174；结果写入 ignored `test-results/review-fixes/`。玩家不需要这些测试工具。浏览器检查本身不等于重跑全部 63 项历史验收，覆盖与故障注入边界见[修复记录](docs/verification/review-fixes.md)。

单独运行 `pnpm run test:browser` 可复验五个分期的静态包和本轮浏览器回归；`pnpm run test:browser --review-only` 仅用于定位修复相关用例，不能替代正式完整验证。分期构建使用 `pnpm run build --mode m1` 至 `m5`，默认 production 为 M5；未知模式明确报错。原始验收证据与已批准规格不由 formatter 重写，新增实现、脚本、测试和维护文档接受 Oxfmt 检查。

包管理已按用户要求从 npm 迁移至 pnpm，旧 npm 命令日志保留历史含义。锁文件导入、依赖等价与本轮安装 / 检查 / 构建结果见[pnpm 迁移记录](docs/verification/pnpm-migration.md)。
