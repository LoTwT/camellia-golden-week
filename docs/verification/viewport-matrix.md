## 整盘边界与调整窗口后的状态

对 16 组配置独立读取数值核查：`fitsBoard=true`、`requiresExpandedViewport=false`，完整 `boardBoundsCss` 均位于 `available` 矩形内。1366 视口画布为 1366×644，可用矩形 `(248,8,916,628)`；1920 视口画布为 1920×956，可用矩形 `(248,8,1470,940)`。边界与可用矩形最接近处仍有 4 CSS px 余量。这个数值检查针对渲染边界；诊断面板的 DOM 遮挡另按上文记录。

C 的 24 份前后快照和相邻配置之间均逐字段比较：

- 模式始终为活动中的 `staticPuzzle`，`practice=true`；八次操作前后均回到同一玩家格。
- 球和推车的本次布局始终相同；没有重置到另一个布局或改变待发目标、待发奖励。
- 已完成目标、26 个奖励 ID、9 份永久完成布局、挑战最好成绩、四区数据和物资总数完全相同。
- 八组 `activeTimeMs` 按采集顺序保持单调，从 97,154.7 ms 增长至 159,160.2 ms，没有归零；每次点击、撤销各增加一代保存。

这些记录支持本次 C 活动实例在已测试尺寸、DPR 与缩放切换中保持状态；截图与状态快照不是对窗口调整瞬间每一帧的录屏。

D 七组 `before / paused` 以及补充快照均保留相同初始幽灵状态、玩家位置和全局进度。它们全部采于恢复准备倒数，`activeTimeMs=0`、灯尚未点亮；恢复按钮重新给出 3 秒倒数属于正常恢复行为。**因此，这批 D 数据不能证明非零幽灵时钟、已移动幽灵或已点灯状态跨窗口调整时保持，也没有逐组点击结果。**
