# R1 视口与本机性能验收

本轮使用当前 M5/content6/rule4/schema3，独立 Chrome 153.0.8010.36、macOS 26.6.2（25G83）、Apple M1 Pro、32 GiB。运行器为 [r1-visual-performance.ts](../../scripts/browser/r1-visual-performance.ts)，规则阈值仍取 [architecture §2.1 / §3](../spec/architecture.md) 和 [acceptance V01 / V05](../spec/acceptance.md)。旧版 64 电视盗取场景的历史数据不作 R1 通过依据。

## 正常输入来源

中心教学使用正常“新游戏”。其余场景由文件选择器导入 [本轮正常主线实际 earned-save](../../tests/fixtures/r1/m5-main-earned-save.json)，点击确认替换，再用传送菜单、方向键、F 交互和正常挑战选择进入。导入文件 SHA-256 与全部正常命令写入每份证据。离线纯规则只规划合法路径，不把离线状态写入浏览器；浏览器只读诊断用于核对位置、时钟和资源。

正式防火墙需要先完成教学，主线跳过计分的源档尚未满足，因此本矩阵选择正常可进入的防火墙教学场景。它保留相同 5×4 专用舞台及双侧分数屏。首次脚本误选正式档位被规则拒绝的记录保留，不把拒绝后的外层场景算作防火墙通过。

## V05：连续有效场景

当前最密的盗取03有 64 个平面格。两个全新浏览器上下文分别通过正常 UI 到达其练习初态，在标准和低画质下，各进行 60 次正常 Up/Down 可逆移动。静音、减少动态、减少闪烁均关闭，音频实际启用。浏览器 viewport 为 1920×1080，浏览器 DPR2，渲染 DPR 分别为 2 / 1。

只读 RAF 采样从首个有效帧开始，要求页面可见、有焦点、没有对话框、渲染准备已结束且始终为盗取场景；中断直接失败，不拼接窗口。每档取得 3601 个原始帧间隔，累计及首尾时间均为 **60014.3 ms**。60 次输入的完整操作时段分别为 66.181 / 65.081 秒，比帧采样窗口稍长，二者没有混称。撤销深度实际增加 60，物件布局和永久进度保持不变。

| 实测                       | 标准画质 |  低画质 | 原阈值     |
| -------------------------- | -------: | ------: | ---------- |
| 帧间隔中位                 |  16.7 ms | 16.7 ms | ≤16.7 ms   |
| 帧间隔 p95                 |  16.7 ms | 16.7 ms | ≤25 ms     |
| 帧间隔最大                 |  16.8 ms | 16.8 ms | 报告观察值 |
| 60次物理输入到玩家可见 p95 |  32.4 ms | 32.9 ms | ≤100 ms    |
| 玩家可见终点最大           |  33.5 ms | 33.4 ms | ≤140 ms    |

输入观察器在实际 keydown 捕获阶段取起点，检测目标 DOM 格中的玩家可见后等下一 RAF 取终点；这是平面终端的可见端点上界，不冒称普通世界 Three.js 玩家动画或跟随镜头测量。中位阈值仅容忍 `1e-7 ms` 浮点误差；JSON 保留未四舍五入的数值。

原始证据：[标准](r1-evidence-files.md#e-c6e4fd52283d7cab)、[低画质](r1-evidence-files.md#e-3af10fafde7183d5)、[汇总](r1-evidence-files.md#e-ba9508374b4fbae6)。命令：`node scripts/browser/r1-visual-performance.ts --performance-only`；最终运行日志本机 `/tmp/r1-performance-third.log`，退出 0。

### 保留的预采样失败

前两轮尚未开始 60 秒采样就失败：辅助离线模型在 Settings 后错误推进内部时间，下一次预测移动形成超过 250 ms 的 clockGap，误判没有可逆移动。真实浏览器仍在合法初态；修复辅助模型以权威 clock.lastMonotonicTimeMs 为时间来源后，原地 Up/Down 路径实际通过。保留 `standard-first-planner-failure.json/png`、`standard-failure.json/png` 和规划记录；不将其描述为游戏必须离开初态才能移动，也不删除失败历史。

## V01：56 个实际视口组合

7 个场景 × 1366×768 / 1920×1080 × 浏览器 DPR1 / DPR2 × 游戏缩放滑块 0.75 / 1.5，共 **56 组实际通过**。[逐组汇总](r1-evidence-files.md#e-9be7fb9c29441e0b) 包含截图文件名、源参考、正常命令、实际 viewport / devicePixelRatio / visualViewport.scale、render DPR、点击位置及点击后的权威位置。

这是 Playwright 浏览器 viewport / deviceScaleFactor，加游戏原生范围控件 Home/End 输入；**没有使用 CSS zoom，也没有冒称浏览器原生页面缩放**。实际 visualViewport.scale 为 1。每组实际鼠标点中一个正常合法邻格，并核对位置；随后键盘 Escape 暂停，改变为另一个合同视口，房间、布局、时钟、位置和永久记录保持不变。世界及静态盘面的缩放受整盘适配上限限制，防火墙/杀毒采用固定专用舞台；盗取03是固定响应式平面面板，`actualGameZoom=null`，不会把未使用的 Three 相机缩放当作 DOM 缩放。

## 普通世界端点：修复后通过，失败保留

正常导入并传送仓库，标准画质、DPR2、缩放1、未减少动态，`warehouse.t.0.0 ↔ warehouse.t.1.0` 正常键盘往返10步。只读keydown捕获起点，RAF观察 displayedFocus 首次等于新的目标，并记录renderer实际静止玩家/镜头完成的 frame-end 时刻。

100 ms表现目标版本物理输入到镜头首次观测为 **119.3–121.9 ms，6/10超过120 ms**；物理输入到玩家渲染端点 **119.1–121.9 ms，全部≤140 ms**。renderer自身起点到端点为114.1–117.8 ms。不能因renderer自身≤120就省略输入处理时间并称物理输入镜头通过。

[失败10步](r1-evidence-files.md#e-0814935cab2f5a31)、[失败断言](r1-evidence-files.md#e-2fe9627a3adab712)。更早一轮将玩家/镜头合并端点作为上界，首步120.9 ms失败，保留 `world-movement-first-combined-endpoint-failure.json`。

根因为100 ms表现目标叠加输入处理和帧量化超出镜头预算。主任务将共用表现时长 `MOVEMENT_TRANSITION_MS` 从100改为90 ms，并实际执行相关layout测试通过；权威输入间隔、时钟与游戏规则不变。重新构建后同一正常路线10步全部通过：

| 修复后实测                   |     最小 |     最大 | 原阈值      |
| ---------------------------- | -------: | -------: | ----------- |
| 物理keydown→镜头首次到目标   | 101.1 ms | 105.4 ms | 每步≤120 ms |
| 物理keydown→玩家实际渲染端点 | 101.0 ms | 105.2 ms | 每步≤140 ms |
| renderer自身动画端点         |  96.2 ms | 100.8 ms | 原始观察值  |

[修复后完整10步](r1-evidence-files.md#e-f41f8e2c4cd9b77c)，命令 `node scripts/browser/r1-visual-performance.ts --world-movement-only`，日志 `/tmp/r1-world-movement-90ms.log`，退出0。包含到达该场景后的首次移动，没有丢弃热身超限或重采样挑选。前述56视口组与60秒盗取性能采样在100 ms版本执行；改为90 ms没有改变静态布局，盗取DOM不使用该世界动画时长，因此不重跑无关矩阵与密集面板样本。
