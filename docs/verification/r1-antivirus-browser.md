## 执行与结果

2026-09-12 UTC 10:29:01–10:31:56，Chrome 153.0.8010.36，独立 context，1512×900。时间范围取本轮独立日志创建时间和最终结果写入时间。执行 `node scripts/browser/r1-antivirus.ts`，从 M5 新游戏按当前 main witness 的正常键盘命令通过 A 区，再沿 B 首列下三格进入杀毒终端。只读快照用于核对位置、已呈现目标与屏幕坐标，所有游戏操作均为正常按键、按钮或鼠标点击，没有导入旧档或注入内部状态。

完整证据为 `docs/verification/evidence/r1-browser/antivirus/result.json`、三份 `*-result.json` 及各档 `*-paused.png`、`*-overflow.png`、`*-success.png`。浏览器页面错误为空。

响应范围为输入前只读观察时刻减该目标实际生成时刻；脚本要求目标已存在至少 250ms 才发物理点击。三档均等待首星，实际一次清除 7 个普通目标，再持续点击到达分数。重度 650ms 的生成压力已由此次标准模式实际浏览器输入验证，纯规则理论可解不再单独充当该项通过依据。

每档先不输入直到普通目标数量达到 10，实际以 `overflow` 失败，星目标不计入数量。失败后正常点击“再挑战一次”，重新选择同档位开始成功尝试。三档都在运行中打开暂停菜单，450ms 内权威活动时间与目标状态完全不变，然后正常继续并等待完整倒计时。

中档暂停时正常勾选静音、减少闪烁与减少动态，350ms 间隔的 canvas 截图字节相同；随后恢复原设置。三档成功末态都明确断言标准画质、非少动态、非少闪烁；少效果验证没有替代标准模式通过。首星前实际 DOM 同时包含蓝色数字 1、紫色数字 2 和星形 ★，计数为 7 / 9，确认新 projection 的辅助标记已经实际呈现。

## 失败保留与边界

此前开发脚本及并行浏览器执行的失败样本保存在同目录，分类见该目录 README。并行一轮曾在标准轻度首星清 7 后出现运行中 clockGap，脚本停止，未自动恢复。该次仍保留为失败，不能据此次独占通过断言其根因已经查明。独占完整三档没有运行中暂停，也没有使用准备阶段恢复；旧 `startup-recovery.json` 的文件时间为 UTC 10:23:37，属于更早尝试，不属于本次 UTC 10:29 开始的通过记录。

脚本只允许新档首方向键前，以及首次 B 舞台准备期 `activeTime=0`、目标为空、倒计时为正、唯一原因为 clockGap 的各一次正常继续，并记录使用情况；进入运行后任何非预期暂停都直接失败。本次通过没有放宽该边界。

局部构图、三视口点击尺寸与供电图形在 [专用 UI 记录](../references/r1-ui-implementation.md) 中单独验证。本记录的 9 张实际截图为暂停/失败/成功状态，未伪装成无遮挡运行帧；C 场景与整个游戏的全流程、跨版本存档回归由主验收记录负责。
