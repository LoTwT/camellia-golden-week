## 固定操作见证

唯一命令记录为 [m1.json](../../../src/content/witnesses/m1.json)，重放入口为 [validate-content.ts](../../../scripts/validate-content.ts)，共用规则检查为 [validate.ts](../../../src/content/validate.ts)。所有步骤只有公开 `GameCommand` 与单调时间；没有设置位置、分数、目标或门状态的命令。

地图导航在制作时按当前合法地形、覆盖和门条件生成确定性四向命令，再冻结到 JSON；运行校验直接重放这些命令。路径没有穿过关闭门，也没有把未成功房间当作普通捷径。迷宫使用固定安全动作逐步走，防火墙使用其固定见证的正常四向输入；每次等待拆成不超过 250ms 的 Tick，经过真实的引擎准备倒数 / 观察状态。

| 见证 ID                               | 命令数量 / 合成单调时间 | 实际通过结果                                                                                                                                                       |
| ------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `m1.world.main-path`                  | 40 条 / 7,360ms         | 新档完成教学、路线增幅、迷宫 01、`a.main`；物资 6、A 数据 20；迷宫 02 / 03、侧路、防火墙全部未完成                                                                 |
| `m1.world.full-collection-and-return` | 1,309 条 / 252,320ms    | 先走上述主路径，再取得 M1 全部 6 个奖励 ID、26 单位、A 首访 80 数据；物理返回中心和重进 A；穿过保留完成布局、迷宫独立练习、再次打内层、重复拾取和终端交互后仍为 26 |

全收集见证中的检查点依次记录：主路径未做可选内容、B 未收录边界、首访全收集、返回中心、重新进入 A、练习保留永久进度、重复领奖仍为 26、已激活地图传送。最终回到 `a.t.0.0`，保持探索模式，`scopeCompletionHistory` 含 M1，`warehouse.complete` 未完成，`campaignCompletedAt` 为空。

schema 2 加入保留完成布局后，现行见证按新运行规则重新记录：重访入口自动进入完成态，普通行走穿过局部出口或明确返回，F 才另起练习。早期 schema 1 的 1,302 条 / 251,340ms 记录及 M1 冻结树 `7bb7a2622333ad0859f40b4e228ad4a780fdc3f2` 保留其历史含义，不能用旧入口变普通格的操作证明现在的局部完成布局已保留。

防火墙正式档的顺序为**核心 → 深层 → 内层**，每次先领取该档物资，再开始下一档；这条路线实际验证三个正式档和三个奖励门互不依赖。完整见证只产生 6 个首次领取反馈，与已领取 ID 数相等，后续练习 / 重打 / 重访没有新增领取事件。

这是 Node 规则层的合成时间见证，**不是浏览器实操时长或录屏**。它证明当前地图和规则能够依照正常命令完成；实际键鼠、视觉表现、存档故障、浏览器矩阵与性能仍由相应阶段验收记录提供证据。

## 校验覆盖与阶段边界

`validateCatalog` 检查完整目录的稳定 ID、26 条奖励 / 130 总量、各阶段 26 / 51 / 81 / 130、每区 5×20 数据、profile 分母、主路径依赖和目标有向无环关系。`validateContent` 检查实际装配 profile 的地图结构、唯一坐标、未知 kind、引用闭合、生产者与效应链、入口 / 出口安全、传送落点、覆盖清除对象和内容来源引用。

M1 首次校验时 `AVAILABLE_PROFILE=M1`，当时未来目录的账本数字通过不代表 B / C / D / 仓库世界已通过。当前阶段由[实施进度](../../verification/implementation-progress.md)及 [M2 记录](world-m2.md)维护；预制的 27 条静态和 18 条实时独立规则见证不替代后续世界流程，未收录世界仍须输出“未验证”。

稳定快照可从 `replayWorldWitness` 返回的最终状态或具名检查点取得，供主存档层序列化 / 迁移测试。此处只返回数据，不写存档、修改内容文件或运行自动修复。
