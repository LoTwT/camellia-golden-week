## D 的固定节点

权威数据为 [d.json](../../../src/content/areas/d.json)，注册记录为 [d-registration.json](../../../src/content/areas/d-registration.json)。原点 `(0,0)` 是 D 首入传送点，x 向右、y 向下；未列出的坐标不存在。世界地板不包含活动幽灵，幽灵及灯只存在于两个独立实时棋盘。

| 路线 / 对象                | 世界坐标与连接                    | 结果与返回                                                                      |
| -------------------------- | --------------------------------- | ------------------------------------------------------------------------------- |
| 入口 `d.teleport.point`    | (0,0)                             | 首达激活 `d.teleport`；入口向东、北、西、南分别有权限线索                       |
| `d.to.c`                   | (1,−1) → `c.t.0.0`                | F 返回 C 的安全入口，不要求 D 权限或隐藏数据                                    |
| `d.ghost.01.entrance`      | 东侧 (2,0)，F 打开；外层返回同格  | 原内部入口 `d.ghost.01.tile.0.2`；首次成功开放 (3,0) 的门，成功安全侧为 (4,0)   |
| `d.permission.01` / 物资   | (5,0) / (6,0)                     | 前置只为幽灵 01；F 取得权限及 20 数据，下一格独立拾取 5                         |
| `d.ghost.02.entrance`      | 北侧 (0,−2)，F 打开；外层返回同格 | 原内部入口 `d.ghost.02.tile.0.2`；首次成功开放 (0,−3) 的门，成功安全侧为 (0,−4) |
| `d.permission.02` / 物资   | (0,−5) / (0,−6)                   | 前置只为幽灵 02；F 取得权限及 20 数据，下一格独立拾取 5                         |

| `d.hidden.terminal` / 物资 | (−3,−5) / (−4,−5)                 | 独立的第五项 20 数据和 5 单位物资；不参与 `d.main`                              |
| `d.ghosts.door` / 物资     | 东末端支路 (6,1) / (6,2)          | 仅两个幽灵完成后由 `d.ghosts.cleared` 开门，独立拾取 5；不要求权限终端均完成    |

四权限各自可以原路返回入口，幽灵入口采用显式 F，普通往返经过入口格不自动开始练习。四权限目标聚合为 `d.main`，第五条隐藏数据没有进入此聚合；两个幽灵聚合为 `d.ghosts.cleared`，也不读取四权限、回访或仓库。权限和物资都放在世界安全侧，危险尝试没有永久拾取实体。

双幽灵物资另有安全绕行 (5,0) → (5,1) → 门 (6,1)。世界接口验证发现，若只能从 (6,0) 进入，未确认权限 01 时，其物资格会阻挡该路线，使额外物资暗含权限 01 前置。2026-09-11 在尚未发布的 M4 地图中补入普通格 `d.t.5.1`；原实体、坐标和奖励 ID 均保留，且新增格不能绕过双幽灵门。

### 三个严格分离的隐藏组

三个组的所有格均为 `initialDiscovery=false` 且写有对应 `hiddenGroupId`。普通相邻发现不会穿透它们；未揭示时，点击、投影与地图路线不能用这些坐标。

| 揭示组                 | 指定唯一来源                | 完整格集合                                                    |
| ---------------------- | --------------------------- | ------------------------------------------------------------- |
| `d.group.permission03` | `d.reveal.03` 的 F 效应     | (−2,0)、(−3,0)、(−4,0)、(−4,−1)、(−4,−2)、(−5,−2)             |
| `d.group.permission04` | `d.reveal.04` 的 R 效应     | (0,2)、(0,3)、(0,4)、(1,4)、(2,4)、(3,4)                      |
| `d.group.hidden`       | `d.reveal.hidden` 的 F 效应 | (−2,−1)、(−2,−2)、(−2,−3)、(−2,−4)、(−2,−5)、(−3,−5)、(−4,−5) |

揭示允许后续逐格发现，不会把整条支路标为已访问。权限 04 的增幅只清上述两格，不能清其他区域的覆盖或顺便揭隐藏数据；两观察点也不清以太。

## A / B 回访合并

[revisits.json](../../../src/content/areas/revisits.json) 使用 `includedFrom:4` 及分区 `areas` 数组。装配时仅把新增格、实体、房间和来源列表合并进原区域，再按 profile 过滤；M1–M3 不加载这些新坐标和实体。原 A / B 文件不需要修改。

| 区域 | 与既有地图的唯一连接              | 固定新增路线                                                                            |
| ---- | --------------------------------- | --------------------------------------------------------------------------------------- |
| A    | 原普通格 `a.t.3.4` → (4,4) 回访门 | (5,4) 富集节点 → (5,5)、(5,6) 覆盖 → (6,6) → (7,6) 数据终端 → (8,6) 物资门 → (9,6) 物资 |
| B    | 原普通格 `b.t.1.3` → (2,3) 回访门 | (3,3) 富集节点 → (3,4)、(3,5) 覆盖 → (4,5) → (5,5) 数据终端 → (6,5) 物资门 → (7,5) 物资 |

两个入口门都只引用 `gate.d.main`。各自富集节点保留 `a.revisit.nexus / b.revisit.nexus` 事件，R 不产生回访数据；玩家必须走到 `a.revisit.terminal / b.revisit.terminal` 后 F 才取得数据并开放自己的物资门。物资分别使用账本已有 `a.supply.revisit / b.supply.revisit`，各为独立 pickup 5 单位。两条路线无互相条件，原路可返回，不连接既有主机关的成功侧以形成绕过。

## 中央仓库

[warehouse.json](../../../src/content/areas/warehouse.json) 保留独立场景 ID `warehouse` 和统计区 `hub`。原中心 `hub.to.warehouse` 在 M4 恢复为可执行入口，沿用唯一 `gate.warehouse`：四区各五项数据齐全，不读取物资或计分挑战。

安全折线为 (0,0) → (1,0) → (2,0) → (2,−1) → (2,−2) → (3,−2) → (4,−2) → (5,−2) → (5,−1) → (5,0) → (6,0) → (7,0)。最终格的 `warehouse.final.terminal` 同事务提交 `warehouse.complete` 和 `hub.supply.final` 九单位 grant；没有额外敌人、动作战斗或物资前置。

入口另一侧 (0,1) 为 `warehouse.to.hub`，F 返回 `hub.t.0.0`。仓库首次到达激活自身传送点；最终终端后仍可原路退出或使用已激活区域传送点。重复最终交互不产生第二次奖励。
