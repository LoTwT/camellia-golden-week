### C 区组合机关

`a / b` 是两只信号球，`K` 为推车，`1 / 2` 为基站。球 a 的目标是站 1，球 b 的目标是站 2；站是地板层。

```text
#######
#.2.1.#
#.b...#
#.a...#
#....K#
#S....#
#######
```

| 对象 | 稳定 ID                | 初始坐标 / 目标                                  |
| ---- | ---------------------- | ------------------------------------------------ |
| 球 a | `c.routing.01.ball.01` | `(2, 3)` → `c.routing.01.station.01` 的 `(4, 1)` |
| 球 b | `c.routing.01.ball.02` | `(2, 2)` → `c.routing.01.station.02` 的 `(2, 1)` |
| 推车 | `c.routing.01.cart.01` | `(5, 4)`，不设虚构的停车目标                     |

可解见证先从下侧把车推到 `(5, 3)`，再从左侧推动球 a，球被车挡在 `(4, 3)`。随后可把球 a 向上送入站 1，把球 b 送入站 2；两球最终入站的顺序有两种见证。没有先放车时，球 a 会滑到右边界 `(5, 3)`；右侧整列是墙，玩家无法站到其右侧将它推回第四列，因此形成不可逆死角，必须撤销或重置。

## 接口与验证边界

`createStatic` 返回初始状态及玩家格 ID；`moveStatic / undoStatic / resetStatic` 接收主引擎当前玩家格，返回新状态、新玩家格、完整前后布局、合法性、失败 / 成功和中文结果。`currentLayout` 不含当前玩家位置；入口基线和撤销快照包含玩家与布局。历史最多 256 步，不随存档持久化；入口基线可序列化，刷新丢弃历史后仍可重置。

谜题成功进入 `complete` 且清空历史。全局主引擎必须在同一事务完成目标、开放对应 pickup、保存完成布局并把玩家送到世界安全出口；谜题模块不授予物资、不修改永久门。独立练习由重新创建静态实例完成，不能回写关闭已提交的全局状态。

`validateStaticDefinition / validateStaticState / validateStaticContent` 校验原始未知输入：包括 kind、有限整数坐标、引用、占格、必经路径、同色数目、重置基线、未知字段及见证实际结果。存档层仍须校验临时目标 / 奖励 ID 的全局归属，并剥离撤销历史。当前静态内容没有局部开关，因此非空 `activatedLocalIds` 会被拒绝；以后增加可逆开关需要显式扩展内容合同及校验。

## 完成布局的永久保存与可通行回访

2026-09-11 补齐玩法合同的完成布局要求。`ProgressState.completedRoomLayouts` 按静态 RoomId 保存第一次真实成功后的 `objectTileById / visitedTileIds / activatedLocalIds`；不存当前玩家位置、第二份完成布尔、待发结果或撤销历史。记录与目标 / 奖励在同一成功事务写入，成功仍回世界安全出口。物体保留本次合法解的真实位置，不能从标准答案重新生成；独立练习的成功、失败或放弃均不能替换该记录。

已完成入口自动进入 `mode=completedRoom`，`activeCompletedRoom` 只指明房间与世界返回锚点，当前玩家仍唯一保存在 `playerPosition`。显示完整局部布局，允许普通四向 / 相邻点击，记忆危险和一笔画重复访问限制停用；对象保持阻挡并不再接受推动。Z 与重置不会作用于永久结果；F 或 `PracticeRoom` 从固定初态另开练习。`ExitRoom` 回世界安全入口。

完成态出口的工程选择：记忆迷宫使用原 `exitTileId`，一笔画使用原 `endTileId`；球 / 推车及盗取使用内部 `startTileId` 作为完成态出口垫。入场不连锁退出，必须先离开再走回出口垫，才回 `world.successExitTileId`。它不改变首次解谜的成功条件，也不增加世界坐标。投影将该格标为“已完成房间出口”。

安全入口由 `validateCompletedStaticEntrySafety` 在内容校验中检查。记忆 / 一笔画没有物体；盗取成功对象只在槽位，起点不与槽重合；球在指定基站，推车的可推区域按前后地板作保守遍历。当前推车从 x=5 开始，x=6 全是墙，无法向左推动，因此永不占据 (1,5) 起点。任何可能让推车堵住完成态起点的新布局会被拒绝，不能在重访时临时挪动真实物体。

`validateCompletedStaticLayout` 严格检查布局字段、对象引用 / 占格、成功匹配和安全入口 / 出口；一笔画完成记录的 `visitedTileIds` 是完整集合，顺序不再具有活动路径含义。`isCompletedStaticPosition` 检查访问态地板和冻结对象占格，允许玩家站在原迷宫危险格。schema 2 的保存与旧档迁移由[工程记录](../../verification/implementation-progress.md)及保存测试维护：无物体旧完成态可以显式回填其确定布局；缺少真实推物结果的旧档不能猜测标准解。

`node --test tests/completed-rooms.test.ts` 实际 **15 / 15 通过**：九房从真实替代解提交并重访，危险 / 重复格恢复通行，物体冻结，出口和返回，练习不替换首次对象位置，非法完成记录 / 堵入口内容拒绝，以及成功事务与旧快照隔离。M1 / M2 当前世界见证已重录，30 次 A/B 往返实际进入完成迷宫并走到内部出口；详见[世界 M1](world-m1.md)与[世界 M2](world-m2.md)。这些新增证据不改变上文初次 46 项静态规则测试的历史范围，也不代替浏览器实操和视觉验收。
