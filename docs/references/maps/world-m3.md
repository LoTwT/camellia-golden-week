## 固定坐标与进入返回

地图共 41 个地板格，范围 x = −6…8、y = −4…2，格 ID 为 `c.t.x.y`。未列坐标不存在，不按外接矩形补地板。地图没有以太覆盖或隐藏组，也不加载 D 坐标、A / B 回访坐标或仓库条件。

| y   | 存在的 x      |
| --- | ------------- |
| −4  | −6、−4、−2    |
| −3  | −6、−4、−2    |
| −2  | −6…0          |
| −1  | 0、5、6       |
| 0   | −2…8          |
| 1   | −4…5          |
| 2   | −6、−5、−4、0 |

| 本版节点                | 坐标 / 安全落点                       | 通行和事务关系                                                                                     |
| ----------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `c.teleport.point`      | (0,0)                                 | B→C 的 `c.t.0.0` 是永久安全地板，首次抵达激活 `c.teleport`；入口不自动反向传送                     |
| `c.to.b`                | (0,2) → `b.t.0.0`                     | 必须当前格 F，返回 B 的已加载安全入口                                                              |
| `c.routing.01.entrance` | (2,0)，放弃回 (1,0)，首次成功到 (3,0) | 踩踏自动进入局部房间；返回点和出口均没有门、物资或自动入口，避免复入或跳过拾取                     |
| `c.routing.door`        | (4,0)                                 | 只读 `c.routing.01`；打开后可沿主轴走到 (7,0)                                                      |
| `c.return.door`         | (2,1)                                 | 同样只读 `c.routing.01`；保护 y=1 的返程环路，不能从入口旁绕过组合机关                             |
| `c.main.terminal`       | (7,0)                                 | 当前格 F 产生 `c.main`；其目录前置只有 `c.routing.01`，C 主路径数据为 20                           |
| `c.to.d`                | (8,0) → 未来 `d.t.0.0`                | 源实体 `includedFrom=4`。M3 装配成 `c.to.d.unavailable`，仅展示“本版本未收录”，没有可执行 D 目的地 |
| `c.theft.01.entrance`   | (−2,−2)，返回 / 成功均同格            | F 打开，退出后不会自动重入；入口走廊与后续两盗取相通                                               |
| `c.theft.02.entrance`   | (−4,−2)，返回 / 成功均同格            | 独立 F 打开，支持同色对象交换槽位的实际替代解                                                      |
| `c.theft.03.entrance`   | (−6,−2)，返回 / 成功均同格            | 独立 F 打开，房间内三色目标不读其他盗取进度                                                        |
| `c.side.terminal`       | (−4,2)                                | 从入口经 (0,1) 向西到 (−4,1) 再向南抵达；仅要求已到达 C 的 `b.main`，不需要组合机关                |

主轴为 (0,0) → (1,0) → 房间入口 (2,0) → 成功出口 (3,0) → 门 (4,0) → (5,0) → (6,0) → 主终端 (7,0)。首次进入 (2,0) 必定切换到局部房间；绕行的 (2,1) 在成功前关闭。因此到主终端既不能读全数据开门，也不能跳过组合机关。完成后可从 (5,0) 向南，经 y=1 回到入口，避免返程再次自动进入房间。

组合机关内部使用 `c.routing.01` 棋盘，与世界板 `c` 分离；物体不可能通过世界传送或房间出口越界。盗取终端采用 `interactionMode=interact`，安全锚点与终端同格符合终端玩法的原位返回。已完成房间按通用规则保留首次成功布局；从入口可重访，练习另行开启，物资门和全局领取不会因重置变化。

## C 六条拾取记录

数量和生产者以 [world.json](../../../src/content/world.json) 的合同账本为准。本地图只放置每条奖励唯一的拾取实体，不在任何成功效应中直接发放 pickup。

| 奖励 ID                | 拾取坐标 | 开放 / 进入方式                                                         |
| ---------------------- | -------- | ----------------------------------------------------------------------- |
| `c.supply.route.entry` | (−2,0)   | 组合机关入口侧的绕行；从入口向西可达，经 (−2,1) 返回，不要求任何 C 谜题 |
| `c.supply.route.exit`  | (6,−1)   | 组合机关成功后，从 (5,0) → (5,−1) → 拾取格 → (6,0) 的安全绕行           |
| `c.supply.theft01`     | (−2,−4)  | `c.theft.01` 成功后穿过 (−2,−3) 独立门，再走到拾取格                    |
| `c.supply.theft02`     | (−4,−4)  | `c.theft.02` 成功后穿过 (−4,−3) 独立门                                  |
| `c.supply.theft03`     | (−6,−4)  | `c.theft.03` 成功后穿过 (−6,−3) 独立门                                  |
| `c.supply.side`        | (−6,2)   | 侧路终端 F 后，经 (−5,2) 门向西拾取                                     |

三盗取奖励门之间没有横向地板，无法从另一扇门后绕入。入口与出口的物资分别占两个明确记录；六条合计新增 30 单位，使 M2 的 51 增至 M3 的 81。五项 C 数据全部在 M3 收录，因此本版 C 分母已经是 100；A / B 仍各 80，回访内容不被提前加载。
