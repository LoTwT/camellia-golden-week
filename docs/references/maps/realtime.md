## 防火墙

四档均为无墙的 5 × 5 方格，出生 `(2, 2)`。每拍图案在制作时冻结为数据；第 b 拍取行优先格号 `(7b + 3j) mod 25`，j 的数量分别为 0 / 5 / 9 / 13。运行时只读取 `beatMasks`，不生成随机图案。图案从该拍前 250ms 生效，仅在玩家移入时检查。

| 挑战                  | profile 起点 | 拍数 | 成功见证命中数 | 结束时间 | 见证 ID                               |
| --------------------- | ------------ | ---- | -------------- | -------- | ------------------------------------- |
| `a.firewall.tutorial` | M1           | 30   | 12             | 15,000ms | `a.firewall.tutorial.witness.success` |
| `a.firewall.inner`    | M1           | 90   | 40             | 45,000ms | `a.firewall.inner.witness.success`    |
| `a.firewall.deep`     | M1           | 90   | 55             | 45,000ms | `a.firewall.deep.witness.success`     |
| `a.firewall.core`     | M1           | 90   | 70             | 45,000ms | `a.firewall.core.witness.success`     |

成功见证从 250ms 开始，每 500ms 以正常方向命令交替向右、向左，达到门槛后停止移动并等待结束。实际规则按移动、时间窗和最高 Combo 判定，不比较该见证字符串；任意合法点击或方向路线均可计分。边界失败见证在 99ms 移动后等待到时，最高 Combo 为 0。规则测试另重放全部 30 / 90 拍，确认同拍最多一次命中、达到上限和首次结束事件只发生一次。

改造映射：原防火墙机制线索 → 独立固定局部棋盘；教学胜利 → 由主引擎开放正式档位；正式成绩 → 由主引擎开放对应物资格。规则模块只返回胜负和成绩，不发永久奖励，不新增开库数据。

## 幽灵房间

`d.ghost.01` 有 9 格，主通路是 `(0,2)` 至 `(6,2)`；另有 `(2,1)`、`(3,1)`。入口 `(0,2)`，出口 `(6,2)`。幽灵路径为 `(2,2) → (2,1) → (3,1) → (3,2) → (2,2)`；灯在 `(3,2)`，仅移除此幽灵。

成功见证 `d.ghost.01.witness.success`：在 250ms 移到 `(1,2)`，真实等待幽灵的 500ms 首步；550ms 移到 `(2,2)`，690ms 踏入灯，830 / 970 / 1110ms 继续右行至出口。失败见证在 140 / 280ms 连续右行，在第二步撞到初始幽灵，回出生点，灯态恢复未亮。

`d.ghost.02` 有 13 格，主通路是 `(0,2)` 至 `(8,2)`；另有 `(2,1)`、`(3,1)`、`(5,3)`、`(6,3)`。第一幽灵与灯沿用第一段的相对布局；第二幽灵路径为 `(5,2) → (6,2) → (6,3) → (5,3) → (5,2)`，第二灯在 `(6,2)`。两条路线没有同刻重合或交换；每盏灯只清自己的一组。

成功见证 `d.ghost.02.witness.success`：右行时间依次为 250、550、690、830、970、1120、1260、1400ms。690ms 点亮第一灯；在第二幽灵于 1000ms 离开 `(6,2)` 后，1120ms 点亮第二灯，最后到达 `(8,2)`。两段都包含实际等待与亮灯，未通过合成“灯全开”初态证明出口可达。

改造映射：原幽灵 / 灯机制线索 → 本版两个固定局部房间；每段成功 → 主引擎打开安全通路；权限与永久物资仍在外层安全侧。此模块没有永久权限或奖励变量，失败无法留下已领取物资后反复重置的支路。

## 时间与集成边界

规则使用输入携带的有效毫秒与递增序号。防火墙和杀毒在截止时先停止，随后忽略同刻输入；杀毒其他同刻事件按过期、出现、输入排序。重复序号、回退时间、未来输入和已结束状态不会重复产生成功事件。

幽灵使用开放的末端 tick：不带输入的 `advanceRealtime(t)` 先处理严格早于 t 的幽灵事件，恰好 t 的 tick 保留，供同刻输入一起结算；下一次大于 t 的推进会处理尚未结算的 tick。这样输入适配器先推进时间、再送当前事件时，仍能统一判断玩家与幽灵意图。显示最多延迟至下一次正常调度，不会先判静止碰撞再遗漏合法跟随或交换碰撞。同刻多个移动最多处理第一个，连续合法移动至少间隔 140ms。

`clock.ts` 不依赖帧数、日期、DOM 或浏览器存储。它维护暂停原因集合、显式恢复标记、剩余准备时间和输入代数。超过 250ms 的前台调度间隔冻结在最后已处理有效时间，返回 `clearInputs`；恢复要求页面、画布与图形条件同时可用，仍存在的系统原因无法强制清除。实时恢复有 3,000ms 倒数，静态模式恢复可立即继续有效观察时间。声音、画质和减少动态设置不参与规则函数。

反馈 ID 仅在当前挑战尝试内唯一；主引擎需结合尝试 ID 或全局修订号映射为全局一次性事件。所有结果由主引擎提交目标、成绩和永久奖励，不能在显示动画结束时再次结算。
