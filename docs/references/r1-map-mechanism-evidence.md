## 2. C 数据盗取可立即使用的机制冻结

### 2.1 直接支持的规则

原手册支持：球受推后连续滑行；未组装基站不能推；同色球与基站组装；组合体每次一格；全部组合体进入匹配供电接口完成。玩家可走灰色斜纹缓冲区，任何组件不能进入。所有三视频均显示扁平终端面板，不能用电视世界房代替。

[第二关原视频](https://www.youtube.com/watch?v=6BtffpZHxn0) 00:14 的日文游戏提示把组装体描述为可停止信号球的障碍物；同时画面显示已组装蓝件仍可在普通格推动。[第三关](https://www.youtube.com/watch?v=ass1F93tyx4) 起始画面清楚显示球、站各蓝橙一对；不能沿用旧三色三箱。

彩色方框是组件本身的边框，会随组件移动，**不是供电接口**。实际接口为带彩色外框的方形凹口，出现于后半阶段；第二关 00:23 和第三关 00:21 的证据截图完整显示它们。两关初始界面未显示接口图形。此事实支持分阶段 UI，但不单独证明精确在哪一帧激活。

### 2.2 具名本版适配：C-R1-COMPONENT-BOUNDARIES

适用 `c.theft.01/02/03`，在原手册基本语义之外冻结以下未知输入边界。理由：原短视频提供成功演示，没有异色冲撞、退接口、拆分或撤销输入；确定规则必须支持死角恢复和合法替代解，不能从单条演示捏造未见过程。

1. 组件每实例保留稳定 `ballId/baseId/color`。未组合分别占一格；组合后一个组合体占一格，同时保留两原 ID，不能拆分或吸收第三组件。同色配对兼容，不读取预设解串。
2. 球扫描推动方向各格；边界、墙、灰缓冲、其他球、任何组合体、异色未组装站均阻挡，球停在障碍前最后普通格。遇第一个同色未组装站，则进入该站所在格并立即组合、停止本次滑行，不继续借剩余距离移动组合体。其他组件不受传递推力，不允许串推。
3. 若球相邻方向即受非匹配阻挡、没有移动或组合空间，整步无效；玩家也不移动，不新增撤销记录。有效推动玩家仅进入球原格，绝不跟随球跨格。
4. 玩家直接撞未组装站无效；推组合体仅测试正前方一格，须为无组件的普通地板或未占用接口，不能进缓冲。玩家进入组合体原格。已组装异色件也可临时经过不匹配接口，但不满足该接口；不把颜色当运动墙。
5. 端口坐标由地图固定。所有必需组件组合后进入供电阶段，显示并激活全部端口；组装阶段未激活端口位置仍是普通地板。激活当次立即计算占格满足关系（不要求人为离开再推回）。端口不阻挡玩家、自由球或错色组合体，但仅匹配组合体满足。阶段触发选“全部必需组件已配对”是本版适配；初始隐藏、后期显示已获画面支持。
6. 在最后一个端口满足前，组合体可推离已满足端口，满足关系随占格重新计算；不消耗/锁死组件。最后全部满足时原子成功并冻结完成实例；继续体验须从练习入口。原版退接口行为未见，允许退出是本版可恢复性选择。
7. 成功条件为全部必需球、站一一合法配对，且每个必需接口由匹配且唯一的组合体覆盖。缺件、多件冒充、球单独压口均不成功。
8. 每个有效动作原子保存玩家、全部组件身份、配对、坐标、供电阶段和接口状态。撤销恢复全部字段；重置恢复实际入场基线并清空历史；放弃丢弃临时尝试，回到明确世界入口。无计时、失败惩罚、额外奖励或数据；不会重置另一房间已完成盗取/推车解锁。

验收：规则测试覆盖每类碰撞、立即组装停止、球长滑与组合一格差异、缓冲仅玩家、无效步不写历史、错色口不满足、接口进出、全部配对成功、撤销恢复身份/阶段、重置/放弃/死角恢复；三关分别取得正常键鼠成功和合法替代解/次序证据。决定冻结不等于“原版一致已证实”或“本版适配已验证”。

## 4. C 世界捕获边界适配

### 4.1 原来源支持及缺口

S13-C1 的四组依次为首组预置物体，之后三组各完成一个盗取取得推车。攻略分别提到堵两角、从另一侧追赶，但未给完整逐步输入或原动作同步定义；第四组方位文字冲突。不能把文字中角落名变成完整原版拓扑。

### 4.2 具名本版适配：C-R1-CAPTURE-RESPONSE

适用于四组有界世界子空间。保持四组、推车、堵路和追赶这三项已确认形态；具体地图须按原图测绘或另列未见支路适配，不继承旧球车入站图。

- 本版采用回合响应：只在玩家有效四向走一格/推一车后检查；无效输入、F 菜单、等待或暂停不让邦布自行移动。一步内先验证并应用推车，再计算玩家候选位置与邦布响应，最后原子提交。
- 触发为候选玩家格与邦布曼哈顿距离 ≤1，或候选玩家格就是邦布旧格。邦布只在自己的有界逃跑通路中四向走一格；不能穿玩家候选格、推车、墙或子空间外。
- 若有逃路，选择与玩家候选格曼哈顿距离最大的邻格；平局用每关显式 `escapePriority`（建议上、右、下、左）裁决，内容内存储该顺序，不依赖对象迭代顺序。仅响应一次，不连续逃多步。不接近时保持原位。
- 若没有合法逃路且本次触发，立即捕获；若玩家候选格为邦布旧格且邦布有路，先让邦布逃开、玩家占原格；无路则捕获并让玩家占原格。捕获后邦布转为已捕获状态，不再占逃跑碰撞格。
- 推车不可推入尚未捕获邦布格；不可拉取、串推或出界。失败推动整步无效，也不触发逃跑。有效动作的撤销恢复玩家、车、邦布及临时捕获结果。
- 永久捕获成功统一在事务提交边界记录。练习成功只记录当前完成布局，不重复奖励；旧 `c.routing.01` 权益按主合同保留。重置不撤销其它房间盗取永久解锁，不复制推车；锁定的后三组没有可推车，UI 明示所需盗取终端，不用隐藏障碍制造假可解局。
- 不额外要求“推车恰在某个唯一答案格”；只根据实际无逃路判定，保留原攻略提到的两角替代方案。地图必须证明没堵车时不能靠出生旁一步白捡捕获，有堵路后可追赶并捕获，且所有解锁/退出入口可达。

这些是精确原逃跑触发未获录屏下的本版规则决定建议，由主任务采纳后才成为实现合同。验收四组分别正常输入成功、无效推不逃、每个平局方向、车封锁/撤销/重置、未解锁与旧档补体验；130物资与四捕获分开验收。
