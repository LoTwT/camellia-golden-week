## 六项实施建议，按优先级排序

### 1. 先把电视改为横向紧密排列

在 `BoardRenderer` 中把重复的格距提为共享 X / Z 参数，以免外壳、屏、图标、当前格框、标签和镜头目标使用不同坐标。建议第一轮使用 `cellStepX=1.00`、`cellStepZ=0.90`；外壳由 `(0.97,0.22,0.94)` 调为约 `(0.97,0.22,0.82)`，玻璃由 `(0.82,0.06,0.69)` 调为约 `(0.82,0.05,0.62)`。保留现有 75° 相机初值，先用几何比例解决差异。

配套将控制条 / LED 的 Z 偏移从 `+0.365` 收到约 `+0.31`，图标的实际不透明范围保持在玻璃内；不能只压缩壳而让旧图标平面或当前格框溢出。第一轮目标是外框显示宽高比约 1.14、横缝约壳宽 3%、纵缝约 1–3%。这些是调参起点，完成后重新量图；现有射线命中继续跟随真实实例矩阵。

### 2. 提亮紫灰边框，重做静态玻璃层次

`bodyMaterial.color` 可先由 `#32313b` 试调至 `#494455`，保留现有实例色与光照，避免同时修改三套因素。普通地板屏底色建议从投影层的 `#25272a` 试到 `#363345`；不是把所有空屏都染成取样最亮的 `#60627e`。

当前 CRT 纹理的黑色暗角终点为 `#07040bda`，乘上深色屏后几乎只剩黑面。建议末端 alpha 从 `da` 降到约 `80–90`，在上半部加入两三块低对比、软边的静态灰紫反光，局部叠加强度约 8–14%；保留细弱扫描线。外壳上缘增加一条极细亮边，控制条上现有 LED 旁增加少量小按钮 / 短槽即可，不需要每格独立复杂模型。

参考图不能证明云状反光对应何种访问状态，因而这些表面细节只作静态材质变化，不新增玩法语义。危险格仍保留非颜色警告符号，墙 / 安全地板仍需可辨。减少闪烁模式使用相同的静态反光，不添加脉冲或全屏闪烁。

### 3. 缩小背景三角面并扩大明暗跨度

当前 `PlaneGeometry(100,100,8,8)` 的基础网格边长为 12.5 世界单位，超过一屏主要棋盘范围，因此截图通常只有一两条大斜线。建议先改为 `32×32` 分段，得到约 3.125 单位的面块；可确定性轻微扰动网格交点，避免整齐对角线贯穿画面。继续合并为一个网格，颜色只在建立时生成。

第一轮可试用 `#6f6887 / #827897 / #9187a6 / #a198b5 / #bbb2cc` 的灰紫组，少量暗面保留 `#605a78`，亮面只占局部。当前已有 `.vignette`，提亮中部时先保留边缘压暗，再用截图核对是否过亮。目标是在一屏能看到约 5–10 块大小不同的多边形，形成原参考的折面感；不能把棋盘遮蔽或新增会干扰危险判断的动态背景。

### 4. 用调整后的物理边界重新拟合局部棋盘

改窄格距后若仍使用 `maxY-minY+2` 作为相机高度，整盘会反而变小。局部房间应根据 X / Z 间距、壳厚度与相机投影后的包围框拟合，加约 0.7–0.9 世界单位总留白，同时避开左右 HUD 的可见范围。1280×720 下，当前 C 盘面约 `[369,108,911,630]`，宽 542px；第一轮可把宽度提高到约 620px、仍保持上下完整，作为本版 7×7 内容的构图目标。它不是原 C 坐标或视口的复刻。

世界探索继续保留工程合同约 9 列 × 7 行的默认可见范围，不以减少可见格数换取放大效果；格距修改后应重算默认范围，保持 0.75–1.5 缩放语义。小窗口先收起侧栏，点击目标不低于 44 CSS px。B 原参考为 5×4，本版 5×5 和 C 的 7×7 不能直接等比套同一个相机距离。

### 5. 优先修正玩家和推车的补制轮廓

当前 C 推车是购物车篮筐轮廓；实际原 C 图中是**箱形正面、圆形面板、底部小轮**。先替换这一张补制图标的轮廓，保留已有稳定资源 ID 和运动规则。球与基站外观未证实，继续保留本版辨识方案及配对数字，不编造其原版匹配。

当前玩家更像方角头盔；A / B 原参考的玩家标记为深色圆顶面、两只明显圆眼和双耳，白色屏底接近中性。建议补制时突出圆眼和圆顶，玩家屏色由 `#e4dbb4` 试到 `#e2e1dc`，当前格边框保留但收细为约 2 CSS px，让白屏 / 轮廓承担主要辨识。标记主体可占玻璃高度约 80–90%，边缘须留白；不添加原参考里的版权文字或整图切片。

这些是对已记录补制缺口的修正，不改变“原版提取资源采用 0”的状态。D 现有幽灵应继续保持暗本体与粉色双眼；原 D 的粉红砖墙不是幽灵，不能通过整屏粉色替换此语义。

### 6. 压缩固定黑色栏，保持目标和数字的阅读顺序

当前 `.game-shell` 顶 / 底栏为 90 / 72px，占 720px 高度的 22.5%；原参考多用悬浮顶栏和较细底部 HUD。保留现有功能与键盘入口，第一轮可调整为约 `68px minmax(0,1fr) 56px`，菜单和底部按钮仍至少 44px 高；字号不靠缩小到难读来节省空间。

右侧 `.progress-rail` 的 37px 主数字可先降到 32–34px，内边距从 18px 到 14px、分隔线外距从 17px 到 12px，使数据 / 物资更紧凑。中文目标维持约 16px，数字继续使用已有 Barlow Condensed；字体仍如实记为替代。当前 C 的左侧计数、说明、短反馈保持既有修正，不重新移到棋盘中间。原作队伍、战斗或外部货币栏不在本项目范围，无需补回。
