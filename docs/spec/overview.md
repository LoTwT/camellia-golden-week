## 1. 目标与约束

做一款可以从新游戏连续玩到中央仓库、关闭浏览器后继续进度的单人本地游戏。玩家在相连的电视格子地图中显露道路、使用阳炎增幅仪、解开机关、完成格子内挑战、回访四区并收集物资。核心体验是“发现阻挡 → 找到规则 → 改变地图 → 打开新的探索空间”。

用户明确确认的约束包括：项目为 `camellia-golden-week`；核心技术栈为 **Vite + TypeScript + Three.js**，linter 使用 **Oxlint**、formatter 使用 **Oxfmt**，**Tailwind CSS 与 Vue 相关生态按需使用**；**优先使用社区整理的《绝区零》素材，整体风格尽可能还原原作**；只覆盖空洞内探索、机关和格子内挑战；移除剧情、空洞外流程和动作战斗；当前仅维护规格与 Agent 配置，不进行工程初始化、游戏实现或 Git 发布操作。其他具体选择由本规格提出，供审阅和后续实现采用。各工具职责见 [工程合同](architecture.md)，资源选择与还原标准见 [美术合同](art.md)。

| 范围 | 本版内容 |
| --- | --- |
| 完整空间 | 中心区、仓储区 A / B / C / D、A / B 后期回访支路、中央仓库；共享一个持续世界 |
| 公共探索 | 四向走格子、未知格显露、以太覆盖、增幅仪、数据、门禁、传送、物资 |
| A 区 | 3 个记忆迷宫、防火墙教学与内层 / 深层 / 核心三档 |
| B 区 | 2 个一笔画、轻 / 中 / 重三档杀毒程序 |
| C 区 | 主地图信号球与推车组合机关、3 组终端内数据盗取 |
| D 区 | 隐藏路线、幽灵与灯、4 条权限路线 |
| 完成后 | 中央终端结算、自由回访、补齐物资和刷新个人最好成绩 |

明确移除对白、短信、剧情演出、城市往返、游戏内日期、真实日期解锁、信赖 / 遗物故事、编队、血量、战斗、养成、活动外兑换。操作教程与机关提示仍保留。无服务器、账号、联机、排行榜、随机地图、肉鸽循环、地图编辑器、手柄或移动端适配承诺。

目标平台为 Windows / macOS 的桌面浏览器，键鼠优先。成品是通过本地 HTTP 服务打开的静态构建；资源随包提供，游玩无互联网依赖。离线不指直接双击 `file://`，也不要求 PWA 安装。

## 2. 证据与还原等级

本规格使用以下三个标签。未特别标注的规范性规则一律属于 **[设计]**。

| 标签 | 含义 | 使用边界 |
| --- | --- | --- |
| [依据] | 本轮阅读到的官方文字或第三方攻略，来源详见 [记录](../references/index.md) | 只支持所列机制 / 结构，不能外推逐格或逐帧精确性 |
| [设计] | 为无剧情、本地浏览器版本确定的规则 | 数量、权重、时序、操作差异均按本合同验收 |
| [测绘] | 尚未取得逐格、逐事件证据的原地图或原参数 | 不生成伪造的“原版坐标”；制作时补来源，无法证实时使用具名重建差异 |

[依据] 官方公告规定四区攻破进度均到 100% 后开启中央仓库，并说明原活动按时间和剧情阶段开放。公告发布于 2024-08-19，活动于 2024-08-21 开始；本版不沿用其解锁日期。[官方活动规则](https://www.hoyolab.com/article/32271763)

还原优先级：地图连接与机关因果关系 → 操作 / 成功失败反馈 → 电视阵列构图 → 装饰。采用手工固定地图，并将原版素材与视觉风格的尽可能还原作为美术目标；资源复用、代表画面和差异核对遵循 [美术合同](art.md)。逐格一致、像素一致、原音轨和原版判定数值一致均不属于当前已验证成果。

最脆弱的前提是素材足以恢复所有原地图。若前提不成立，受影响房间仍按本规格的固定拓扑与机关合同制作，在来源记录中标为“重建”；发布说明不得称该房间精确还原。此处理不改变主推进、目标 ID 或奖励总量。

## 3. 玩家完整流程

新游戏直接出生于中心区。操作提示引导玩家拿到增幅仪，并在第一处富集节点使用一次；该事务立即完成教学并使增幅仪无限可用。之后进入 A 区，依次开放 B、C、D，再回访 A / B 取齐开库数据，进入中央仓库结束主目标。

```text
中心教学
   │
   ▼
A 主路径 ──► B 主路径 ──► C 主路径 ──► D 四个权限终端
   │            │            │               │
   │            │            │               └──► A / B 回访支路
   └────────────┴────────────┴─────────────────────────┐
                                                      ▼
                                     四区必需数据全部取得（各 100%）
                                                      │
                                                      ▼
                                          中央仓库 → 最终终端
                                                      │
                                                      ▼
                                         主目标完成 → 自由补收集
```

箭头表示解锁关系，不规定地图坐标或原作日期。任何已开放区都可回访，进入区域不会创建新副本或重置永久状态。中心区与中央仓库为两个场景 ID，仓库物资归中心区统计。

### 3.1 四类进度分别计算

| 名称 | 精确定义 | 用途 |
| --- | --- | --- |
| 主路径完成 `mainComplete` | 完成指定本区机关后激活主路径终端；D 为四权限齐全 | 开放下一仓储区 / 回访支路，不能读取本区 100% |
| 区域数据 `dataComplete` | 完整版该区必需数据目标全部完成，每区 5 项，每项 20 权重 | 四区均满足后开中央仓库 |
| 物资 `supplyCollected` | 已领取唯一奖励 ID 的整数单位之和 | 独立收集目标，不作主路径或开库货币 |
| 挑战成绩 `bestResult` | 指定规则版本下的最好结果 | 重玩目标；防火墙和杀毒高分不增加区域数据 |

完整数据百分比 = 已完成必需目标权重 / 100 × 100%。开库判定比较目标集合是否齐全，不比较 UI 四舍五入后的数字。数据芯片不能消费或丢失；不使用宝箱数量替代数据。

### 3.2 关卡与门禁合同

下列符号是逻辑 ID，具体物体、位置和连线由固定地图引用；完整目标列表见 [内容合同](content.md)。`all` 表示所列条件同时成立。表中所有“开放”还要求目标内容已被当前 profile 收录；例如 M1 完成 A 后只记录 `a.main`，升级 M2 后 B 才成为实际可进入的地图。

| 被开放内容 / 事件 | 唯一前置 | 到达效果 | 不得作为额外条件 |
| --- | --- | --- | --- |
| A 入口 | `hub.tutorial` | A 可进入，首达激活 A 传送点 | 剧情、日期、物资 |
| `a.main` | `a.nexus.route` 已清除、`a.maze.01` 成功、交互 A 主终端 | A 主路径完成并取得 `a.data.main`；B 入口开放 | 迷宫 02 / 03、防火墙档位、A 全数据、回访 |
| `b.main` | `b.line.01` 成功、`b.switch.shortcut` 激活、交互 B 主终端 | B 主路径完成并取得 `b.data.main`；C 入口开放 | 一笔画 02、杀毒档位、B 全数据、回访 |
| `c.main` | `c.routing.01` 的球 / 推车组合机关成功、交互 C 主终端 | C 主路径完成并取得 `c.data.main`；D 入口开放 | 数据盗取 01–03、C 全数据 |
| `d.main` | `d.permission.01` 至 `04` 全部取得 | D 主路径完成；立即开放 A / B 回访门 | D 隐藏数据、A / B 全数据、任何仓库内容 |
| A 回访 | `d.main`，再到达 `a.revisit.terminal` 交互 | 取得 `a.data.revisit`，可领取该支路物资 | A / B / C / D 数据百分比 |
| B 回访 | `d.main`，再到达 `b.revisit.terminal` 交互 | 取得 `b.data.revisit`，可领取该支路物资 | A 回访完成、任何区域全数据 |
| 中央仓库门 | A / B / C / D 四区 `dataComplete` 全真，且当前包已收录仓库 | 同一事务永久打开，目标指向仓库入口 | 130 物资、高阶挑战、战斗 |
| `warehouse.complete` | 已开库，走到仓库最终终端并交互 | 一次性主目标结算并领取中心区末端 9 单位物资 | 其余物资、所有最高成绩 |

每区主终端只能通过相应地图机关到达，不能在菜单中直接完成。各区首达自动激活入口传送点；M 地图传送仅能使用已激活的点。门开启事件采用幂等结果，不可重复消费或反复关闭。

### 3.3 数据主表与后期回访

以下权重是为可审计推进建立的 [设计]，不是原作百分比分配。

| 区域 | 首访可得数据 | 后期数据 | 完整数据 |
| --- | --- | --- | --- |
| A | 主终端、迷宫 02、迷宫 03、侧路清理终端，各 20 | D 主路径完成后，A 回访终端 20 | 100 |
| B | 主终端、一笔画 02、北侧终端、南侧终端，各 20 | D 主路径完成后，B 回访终端 20 | 100 |
| C | 主终端、数据盗取 01 / 02 / 03、侧路终端，各 20 | 无 | 100 |
| D | 权限 01 / 02 / 03 / 04、隐藏数据终端，各 20 | 无 | 100 |

“主路径可选”不等于“开库可选”：例如可以先跳过 C 数据盗取进入 D，但开库前仍须完成三组数据盗取。计分小游戏及其高难档位只影响物资与成绩；不影响开库。

### 3.4 无死锁约束

1. A、B、C 的主路径条件只引用本区首访内容及已完成的上游条件，禁止引用本区全数据、后期支路或后续区域。
2. D 四权限路线只依赖已开放的 D 主图；四条相互独立，可任意顺序完成。可以含本区静态机关 / 幽灵段，不可要求回访终端。
3. A / B 回访门只依赖 `d.main`。完整数据中的回访目标不得放在中央仓库内部或以开库为前提。
4. 数据取得、门开启、永久奖励均单调增加。移动物体不得永久堵塞区域入口 / 主终端；需要临时堵塞的谜题必须位于可重置的房间边界内。
5. 从每个可进入的房间都能成功、重置或放弃返回安全入口。退出 / 失败不移除已获得的权限，不消耗资源。
6. 新区域的数据不能成为旧版本终点的前提。版本裁剪规则见下一节。

证明方式为“目标依赖图无环 + 主路径操作记录 + 房间恢复路径”。单纯四区图标亮起或忽略机关做几何寻路，均不算证明。

### 3.5 当前目标文案

先按 profile 筛选已收录内容，再按以下顺序只显示一个主目标：中心教学 → 首个未完成主路径 → D 四权限剩余数量 → 回访 A / B → 其他未齐数据的已知区域 → 中央仓库 → 主目标完成 / 可继续收集。M1–M3 一旦完成包内终点，主提示固定为“本版本主路径完成，可继续收集”，不能继续指向未收录的下一区。

玩家先做了别的合法目标时，系统正常认可。提示可指向已知终端或区域入口；不泄露未显露路线坐标。锁门检查条件并显示具体原因，如“完成 D 区四处权限后开放”，而不是“请推进剧情”或笼统“暂不可用”。

## 4. 分期内容与分母

首版选择 **中心区 + A 区首访完整体验**，同时验证探索、静态谜题、实时小游戏、收集和存档。它不是完整版 A 100% 的承诺。最小可做方案是一张地图加一个谜题；该方案无法验证跨模式存档和回访，故不作为用户首个交付。固定数据 + 单一 TypeScript 规则层是推荐方向；不采用程序生成地图或另加游戏引擎。

运行包带 `releaseProfile`，显式列出已收录场景、目标、奖励和包内终点。`included`（此构建收录）与 `unlocked`（玩家已解锁）是不同维度。未收录内容显示“本版本未收录”；已收录但未解锁内容显示具体条件。未收录地图不会成为可点击入口。

| 包 | 已收录地图 / 支路 | 包内终点 | 可领取物资分母 | 区域数据分母 |
| --- | --- | --- | --- | --- |
| M1 | 中心教学、A 首访 | `a.main` | 26：中心 1 + A 25 | A 80；不计 A 回访 |
| M2 | M1 + B 首访 | `b.main` | 51：再加 B 25 | A 80、B 80 |
| M3 | M2 + C | `c.main` | 81：再加 C 30 | A 80、B 80、C 100 |
| M4 / M5 | 中心、四区、A / B 回访、仓库 | `warehouse.complete` | 130 | 四区各 100 |

包内终点完成即弹出“本版本主路径完成”，可继续收集该包全部内容；M1–M3 不写入完整版通关标记，不模拟缺失区数据，不打开仓库。防火墙等可选挑战可以在包内结算后继续玩。

M1–M3 的 UI 使用“本版本数据 4 / 4”或“80 / 80，本版本 100%”，避免声称完整 A 数据已齐；完整数据状态另为 80 / 100。升级 M4 后显示“新增回访数据”，旧 4 项保持已完成，新增项使完整版显示 80%，不是进度丢失。收集分母按已收录清单固定，不能随着玩家解锁逐步变大；升级构建时才变化。

## 5. 去剧情节点改造

| 原节点职责 | 本版替代 | 必须保留的结果 |
| --- | --- | --- |
| 前置委托 / HDD / 角色介绍 | 新游戏与中心教学 | 初始出生、增幅仪能力、A 入口 |
| 增幅仪用尽后离开空洞升级 | 第一次富集节点事务完成后自动无限使用 | 后续富集节点可清除 |
| 日期或剧情开放区域 | 上表的主路径完成事件 | 地图内明确因果和锁门提示 |
| NPC 开放高级挑战 | 地图上的访问终端 | 在原关系位置开放同组挑战，各档可独立选择 |
| 战斗给数据 / 开门 | 一次性清理终端，交互即完成 | 显式列出每个目标、门、奖励结果；不引入替代战斗 |
| D 区问答 | 四条路线末端的权限终端 | 四处到达与探索成本 |
| A / B 回访救援 / 战斗 | 回访数据终端 | 支路开放、数据、物资、返回通道 |
| 纯故事格 / 遗物交付 | 保留可通行装饰或移除占格主体 | 不留下不可触发的剧情门或空奖励引用 |
| 仓库首领与尾声 | 仓库最终终端 | 一次性完成、最后物资、自由回访 |

来源若证实某个节点兼有多种结果，改造时逐项映射；只删除对白而遗漏数据 / 开门事件属于缺陷。前期计划的旧目录、JavaScript 方案和其他项目资产版本不作为本仓库基线。

未来源码、内容和测试预计超过 8 个文件（约 25–40 个，地图 / 谱面数另计），增加一个本地前端应用，远程服务为 0。第一步在当前仓库复查文档 / 文件漂移，按 M1 初始化 TypeScript 工程并制作中心到 A 的连续流程。运行命令合同、文件职责和验证方法见 [工程合同](architecture.md) 与 [验收](acceptance.md)。
