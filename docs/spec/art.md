# 美术资源与视觉还原

[文档索引](../index.md) · [主规格](overview.md) · [工程与运行](architecture.md) · [验收要求](acceptance.md) · [素材来源核对](../references/index.md#6-社区美术素材核对)

> 当前实施状态：2026-09-11 已批准基线并进入 M1–M5 连续实施。2026-09-12 新增的非防火墙还原表现及专用资源已实现，当前正在验收；已交付的历史画面不代表新版要求通过。当前范围、实际验证与限制统一见[实施进度](../verification/implementation-progress.md)，不由合同文字推定验收通过。

用户已确认：**优先使用社区整理的《绝区零》素材，整体风格尽可能还原原作。** 本文替代初版“默认自绘图标、自制声音”的资源选择。初版仅交付文档和来源调查；后续资源与画面交付见[美术实施记录](../references/art-implementation.md)，各轮证据保留其实际版本和核对范围。

## 1. 还原目标与参考基准

目标是「沙罗黄金周」活动时期的电视探索画面。采用原版图标、贴图和可用声音，同时还原电视外壳比例、格距、屏幕亮度、图标占屏、界面排版、字体特征、状态变化与短反馈。后续版本中已改变的界面或社区改色素材，须与该活动参考核对后使用。

保留原作观感与本项目的玩法范围同时成立：剧情、空洞外流程和动作战斗仍按主规格移除；物资、数据、机关和计时规则仍由对应合同定义。使用原图不会自动恢复已移除的功能，也不证明地图和判定数值与原作一致。

目前的相机角度、屏幕范围和配色描述属于实现起点。找到可核对的活动画面后，以对照证据调整视觉参数，并同步工程文档。可读性、键盘操作和减少闪烁要求继续满足；必要差异在验收记录中说明。

## 2. 资源选择顺序

1. 优先复用社区整理的原版图标、UI 贴图、角色标记与相关音效，保留原始轮廓、配色和状态语义。
2. 结合原作活动截图、录屏与文件说明，确认资源对应的界面、版本及状态。哈希文件名、分类目录或截图中的相似外观均不能单独作为匹配结论。
3. 对缺失、无法取得合适版本或使用条件不适用的资源，参照原画面补制，并记录具体差异。自绘、程序化和合成用于这些缺口。

补制仍须遵守已确认的对象轮廓、场景构图和状态含义，不能以“重建”或“补制”代替这些要求。资源取得方式与还原程度分别记录；有明确原图的部分按原图校准，未证实的状态和细节单列，不由相似素材反推规则。

社区上传、游戏原资产、社区原创作品分别记录来源与使用条件；不能将仓库可下载、代码许可证或署名声明直接记为原资产的再分发授权。来源不明确的项如实记录，参考调查与成品采用状态分开维护。实际发布所用的单项文件依据其使用条件处理，不把整个素材仓库作为无差别依赖。

## 3. 按资源类型制作

| 类型 | 首选处理 | 对照重点 |
| --- | --- | --- |
| 电视外壳、底座、屏幕 | Three.js 重建可复用几何，匹配原版外观；有合适贴图时复用 | 外壳厚度、屏幕比例、圆角、格距、透视与阴影 |
| 玩家 / 邦布标记 | 优先原版电视界面对应图标或帧素材 | 轮廓、大小、朝向、待机 / 移动 / 受击状态；不把角色展示图直接当棋盘标记 |
| 机关、数据、物资、传送与危险 | 原版格子图标和状态变体优先 | 未激活 / 激活、领取前 / 后、未知 / 已显露等状态，逐项对应玩法对象 |
| HUD、菜单、边框、按钮 | 优先复用相关 UI 贴图；布局和可交互文字由 DOM / Vue 实现 | 区域标题、数字、留白、边框、按钮状态与焦点；整张截图不作为可交互界面 |
| 字体与数字 | 确认可用的原版字体时采用；否则选字形接近且使用条件适用的替代字体 | 中文字形、字重、斜体特征、数字宽度、描边、行距；替代项列明 |
| CRT、显露、拾取、切换等效果 | 参照原画面用渲染层和界面动画重建，复用适用效果贴图 | 强度、持续时间、发生位置、先后顺序及减少闪烁模式 |
| 移动、开门、拾取、成功 / 失败音效 | 优先匹配可用的原版短音效，缺失时制作接近的反馈 | 起音、时长、响度、与有效时间的同步；本轮未确认完整音效包 |

资源按实际显示尺寸和 DPR 检查清晰度；不要拉伸原图或通过明显锐化掩盖低分辨率。纹理的透明边缘、颜色与滤波在实际棋盘上核对。DDS 等源格式按需预处理为适合当前前端的本地资源，保留源文件标识与转换记录；不凭素材容器格式增加一套运行时引擎。

### 3.1 六类场景的构图与状态对照

本轮非防火墙的原版依据、可定位画面与证据盲区统一见 [S13 还原核对](../references/restoration-audit-2026-09-12.md)。以下是新版制作与验收目标；布局须与[玩法合同](gameplay.md)确定的对象和地图一致，不能仅用装饰画面掩盖仍未实现的对象差异。

| 代表场景 | 必须对照的构图与对象 | 必须补齐的状态证据与规则入口 |
| --- | --- | --- |
| 中心教学 | 电视外壳、玩家标记、未知格与显露后的机关、基础 HUD；保留已建立的中心校准基准 | 正常新档教学与显露前后；公共对象与输入见[玩法合同](gameplay.md) |
| A 记忆迷宫 | 按可定位原版画面还原迷宫外轮廓、分支和转折的视觉关系，区分可行走路径、边界、入口与出口；不能用通用小方阵代替已确认的迷宫形态 | 对照观察、隐藏和行走状态，标出尚未完成测绘的部分；固定地图与记忆规则见[记忆迷宫](gameplay.md#61-记忆迷宫) |
| A 防火墙 | 沿用已修订的电视墙、拍点、移动警报与判定反馈目标 | 依[原版警报核对](../references/firewall-hazards.md)与[防火墙规则](gameplay.md#62-突破防火墙)检查；本轮不以其它场景修订替代既有防火墙证据 |
| B 杀毒 | 中央 **5 列 × 4 行**普通电视，左右各两块大型波形屏；保持四块大屏与中央棋盘的尺寸层级。对照原版计时、侵蚀数据数量及上限提示的位置与含义，区分数量压力与清除成绩 | 蓝色侵蚀数据、紫色侵蚀目标、金色清除目标和玩家须有对应图形及出现 / 清除反馈；补齐目标堆积、批量清除、成功与失败画面。数量、时长和判定仅由[杀毒程序](gameplay.md#72-杀毒程序)定义 |
| C 数据盗取与世界推车／捕获 | 同一类别必须交付两组画面：**独立数据盗取终端面板**，以及**世界电视地图中的推车和逃跑邦布**。盗取面板须分别表达球、不可推基站、可推组合体、电源接口和玩家专用缓冲地形；世界推车保留箱体、面板与轮部特征，逃跑邦布与玩家标记清楚区分 | 盗取面板覆盖独立球 / 基站、组合体、推动、接入及完成状态；世界场景覆盖接近、推车移动、邦布逃跑与捕获。两组对象不可共用含义不清的箱体或圆点替代；推动、组合、地形通行与捕获条件见[玩法合同第 8 节](gameplay.md) |
| D 幽灵 | 还原原图中砖墙迷宫的空间轮廓、墙面与通路关系；砖墙、幽灵、灯和玩家是不同对象，保留幽灵的原版轮廓与屏幕表现 | 补齐幽灵移动、玩家碰撞、点灯前后及通路状态的同场景对照。灯的作用范围、亮灭顺序和幽灵步频未由静态图证实，不在美术层补定；规则见[幽灵段](gameplay.md#91-幽灵段) |

每类场景分别核对 HUD 的位置、层级、数字含义、字体和排版，以及机关图标、玩家标记、操作提示与反馈遮挡。通用外壳或一套 HUD 的对照通过不能代替各场景检查；C 的两组画面必须分别有原参考定位与本版证据，仍计入同一个 C 类别。

图标、动画和声音按同一对象、同一状态逐项配对。短录屏需覆盖实际操作与状态变化，并核对起音、持续时间、响度和视觉反馈顺序；音效使用条件或原录音不足的项注明补制及未核对内容，静态图不能证明声音还原。减少闪烁 / 动态与静音模式保留关键状态文字和清晰标记，不能以关闭效果省略数量、对象类型或成功 / 失败反馈。原作精确时长、速度与灯范围不由本合同新增，统一依玩法合同和 S13 的证据边界处理。

## 4. 素材清单与本地交付

候选来源和已核对范围维护于 [来源记录](../references/index.md#6-社区美术素材核对)。M1 首次采用素材时，在工程约定的 `public/assets/` 内建立清单并保存实际采用文件；仅有候选来源时不创建空资源包。

每项记录至少包含：稳定资源 ID、用途与状态、本地路径、原始文件路径 / URL、来源版本或提交、文件校验值、原作者 / 权利说明、使用条件、尺寸或时长、裁切 / 转换等修改记录、匹配的参考画面。采用状态区分“候选”“已核对采用”“补制”；图标完成度、声音完成度分别统计。

只交付当前 profile 需要的资源及共享项；运行时从本地包加载，不热链社区 CDN。资源替换沿用稳定 ID，保持规则、存档和关卡数据独立。

## 5. 代表画面与验收

M1 批量制作前，先完成中心 / A 区的一张可交互代表画面，包含电视外壳、玩家标记、未知格、已知机关、当前格高亮及基础 HUD。选择可定位的原作画面，在相同视口条件下作对照，校准构图、字体、图标比例和状态反馈，然后复用到其余内容。原图视口或设备无法确认时，记录图片尺寸和可比较范围，不将其当作同视口证据。

每个里程碑补齐其新增区域的美术资源与对照，M5 按第 3.1 节的六类场景完成统一精修。验收证据包括原参考定位、本版截图 / 短录屏、资源清单及剩余差异；“用了原素材”或“整体像原作”不能替代逐项对照。具体检查入口见 [验收要求](acceptance.md#7-表现与浏览器)。

2026-09-12 新增目标须在实现后重新取证，记录对应构建、内容 / 规则版本、视口和操作状态。历史六类图、旧素材清单与旧测量保留原始含义，不能因规格已更新而将新版项目标为通过；缺少同对象或同状态的原参考时明确标为“原版一致性未验证”。这些未知部分若按[主规格 §2.1](overview.md#21-待核准事项的关闭规则)形成适配决定，完成实际验证后可记“本版适配已验证”，不能覆盖已确认的构图或对象要求。
