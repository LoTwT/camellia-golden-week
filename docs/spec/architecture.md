## 1. 技术选择与职责

核心栈固定为 Vite + TypeScript + Three.js；用户指定 linter 使用 **Oxlint**、formatter 使用 **Oxfmt**，并允许在有实际需要时使用 **Tailwind CSS 与 Vue 相关生态**。按需可用不表示这些界面依赖已经安装或必须一起引入，采用条件见本节后文。

UI 以 HTML / CSS 为基础，音频使用 Web Audio。唯一运行应用是浏览器前端，没有后端、数据库服务或第三方账号。开发环境使用 Node 24 LTS 系列与 pnpm；当前固定 Node 24.18.0、pnpm 11.25.0。`packageManager` 和 `engines` 声明版本，`pnpm-workspace.yaml` 维护安装设置，提交 `pnpm-lock.yaml` 并以 `pnpm install --frozen-lockfile` 安装。此次按用户要求由 npm 迁移，实际等价检查与运行结果见[pnpm 迁移记录](../verification/pnpm-migration.md)，不复制其他项目的锁文件。

Vite 提供原生 TypeScript 转译，但不执行类型检查，因此 `typecheck` 必须独立运行，`build` 也须包含类型检查。[Vite TypeScript 说明](https://vite.dev/guide/features.html#typescript)

```text
固定 JSON 内容 ──> 校验 / profile 装配 ──┐
                                       ▼
键鼠 / DOM ──> 命令适配 ──────────> TypeScript 规则与权威状态
单调时钟 ────────────────────────>       │
存档读取 ──> 校验 / 迁移 ─────────>       │
                                       ├──> 稳定快照 ──> 存档写入
                                       │
                                       └──> 展示快照 + 一次性反馈事件
                                                  │
                                    ┌─────────────┼──────────────┐
                                    ▼             ▼              ▼
                              Three.js 场景     HTML UI       Web Audio
                                    │             │
                              命中 tileId      玩家点击
                                    └──────> 命令适配
```

图中的 HTML UI 可由原生 DOM 或 Vue 组件实现。规则层不导入 Vue、Three.js、DOM、浏览器存储或音频库。鼠标射线只能提供点击意图的 `tileId`，不能判断门已开 / 机关已完成；UI 只能发送命令，不能直接设置进度。反馈动画中断或渲染丢帧都不撤销规则结果。

| 边界接口 | 输入 | 输出与约束 |
| --- | --- | --- |
| 内容加载 / 校验 | 原始 JSON、profile | 不可变已验证内容，或带 ID / 文件定位的错误；不得静默补未知目标 |
| 规则行动 | 内容、旧权威状态、命令、有效时间 | 新状态、结果码、反馈事件、是否形成稳定快照；无隐藏环境依赖 |
| 时钟推进 | 当前时间、暂停原因、已排事件 | 顺序确定的时间事件；不能按渲染帧计步 |
| 展示投影 | 权威状态 + 可见性规则 | 仅已知格、可见实体、HUD、镜头目标；不把迷宫隐藏答案交给自动寻路 |
| 存档适配 | 稳定快照 / 原始存储字符串 | 已验证载荷 / 保存状态；出错不重新结算玩法 |
| 只读观察 | 当前权威状态 | 深拷贝诊断快照；修改返回值不影响游戏 |

玩法命令使用可辨识联合：`Move / Interact / Amplify / ClickTile / Undo / ResetRoom / StartChallenge / RetryChallenge / ExitRoom / Teleport / Pause / Resume`。不同模式拒绝不适用命令，结果码至少包括 `blocked / wrongMode / paused / unmetCondition / alreadyCompleted / invalidTarget / accepted`，并提供对应中文提示。

TypeScript 启用 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`；使用类型导入及可直接擦除的类型语法，不使用需运行时转换的 enum / 参数属性。Node 运行的脚本 / 测试使用明确的 `.ts` 相对导入，不依赖仅 Vite 能解析的别名。Node 的类型擦除不会做类型检查，也不会按 tsconfig 为运行时重写别名。[Node TypeScript 支持](https://nodejs.org/api/typescript.html)、[TypeScript strict](https://www.typescriptlang.org/tsconfig/strict.html)

### 1.2 按需界面依赖与质量工具

简单界面可直接使用 HTML / CSS；当 HUD、菜单、设置等需要复用组件和管理界面状态时，使用 Vue 3、Composition API 与 `<script setup lang="ts">`，由 `@vitejs/plugin-vue` 接入 Vite。组件接收展示快照并发出用户意图；Three.js 场景对象保留在渲染适配器中，游戏进度仍由规则层维护。采用 Vue 时以 `vue-tsc --noEmit` 检查组件及模板类型，Node 脚本与测试继续纳入独立 TypeScript 检查，不能只通过 Vite 转译就判定类型正确。[Vue TypeScript 指南](https://vuejs.org/guide/typescript/overview.html)

重复布局和响应式样式需要统一工具类时，可使用 Tailwind CSS，通过 `tailwindcss` 与 `@tailwindcss/vite` 在构建期生成本地 CSS；手写 CSS 继续负责特殊视觉效果。Tailwind 只控制 DOM 界面样式，电视格材质与 Three.js 场景表现仍由渲染层处理。[Tailwind Vite 集成](https://tailwindcss.com/docs/installation/using-vite)

Vue 生态按职责选用：重复的浏览器交互可使用 VueUse；跨组件的界面状态确有共享需求时可使用 Pinia；出现独立页面 URL 与浏览器前进 / 后退需求时才使用 Vue Router。Pinia 不保存另一份游戏权威状态，区域传送不等于页面路由。现有单页游戏不需要 SSR、Nuxt 或额外游戏引擎；内容条件枚举和各玩法独立处理器覆盖本次规则，增加新机关种类时显式扩展类型和验收。

Oxlint 和 Oxfmt 作为项目开发依赖安装，分别维护 `.oxlintrc.json` 与 `.oxfmtrc.json`；格式选项先采用 Oxfmt 默认值。`lint` 执行只读检查并将警告视为失败，`format` 写入格式变更，`format:check` 只检查格式。采用 Vue 时启用 Oxlint 内置 `vue` 插件并保留项目所需的默认插件；其 Vue 规则覆盖脚本部分，不能把 lint 通过当作全部模板规则已检查。模板类型由 `vue-tsc` 检查，交互仍按浏览器验收执行。[Oxlint CLI](https://oxc.rs/docs/guide/usage/linter/cli.html)、[Oxlint 插件范围](https://oxc.rs/docs/guide/usage/linter/plugins.html)

通过 pnpm 安装 Oxfmt 包以覆盖 Vue、HTML、Markdown 等文件；采用 Tailwind 时启用 Oxfmt 的类名排序能力。项目 lint 和格式入口统一使用上述工具，不再维护第二套 ESLint / Prettier 配置；Oxfmt 内部使用的格式引擎不属于项目另行选型。[Oxfmt 快速开始](https://oxc.rs/docs/guide/usage/formatter/quickstart.html)、[Oxfmt 格式支持](https://oxc.rs/docs/guide/usage/formatter/language-support)

当前没有阻塞 M1 的其他技术栈确认项。包管理、规则测试、本地存档与音频沿用本文默认方案；M1 实现者按上述条件决定界面依赖并记录实际采用项。只有新增联网服务、账号 / 云存档、桌面安装包或改变目标平台等超出当前范围的需求，才需要重新讨论相应技术选择。

## 2. Three.js 表现

美术以社区整理的原版素材优先、整体风格尽可能还原原作为目标。资源来源、采用顺序、字体与状态变体、代表画面对照统一由 [美术合同](art.md) 维护；本节定义渲染和交互实现边界。

使用 WebGLRenderer 与正交相机，电视外壳是有厚度的程序几何，屏幕、图标、覆盖和当前格高亮分层绘制。同形外壳共享几何 / 材质，使用 InstancedMesh；变动屏幕按实例属性或受控贴图更新，不为每格建立独立动画循环。正交投影保持物体尺度，实例化减少重复对象的绘制调用。[OrthographicCamera](https://threejs.org/docs/pages/OrthographicCamera.html)、[InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)

规则坐标映射到水平棋盘 X / Z，规则 x 对应 +X、规则 y 对应 +Z。相机不旋转方位，+x 在屏幕右、+y 在屏幕下；俯视角初值为相对水平面 75°。这一外观数值是本版起点，不是原作测量。

### 2.1 构图与交互

默认镜头围绕玩家保留约 9 列 × 7 行的局部范围，使用当前画布尺寸确定正交范围。缩放基于默认范围 0.75–1.5 倍，且屏幕点击目标不能小于 44 CSS px；小窗口优先收起侧栏，而非把棋盘缩成不可点的点阵。不提供自由旋转；区域图承担远处总览。

普通移动后镜头在 120ms 内跟随至新目标，逻辑命中始终以当前展示矩阵映射；动画中不能点到已换位置的旧格。房间 / 区域切换的遮罩初值不超过 300ms，清空输入，目标格加载完再恢复。机关打开 / 拾取只使用局部反馈，不播放长距离强制巡镜。

| 画面区 | 内容 | 行为 |
| --- | --- | --- |
| 顶部 | 区域名、单个当前目标、保存状态 | 保存状态仅显示已保存 / 保存中 / 未保存与可操作原因 |
| 棋盘主体 | 电视格、玩家、已知机关、局部提示 | 当前格靠边框和角色标记识别，不能只靠颜色 |
| 侧栏 / 可折叠区 | 当前区数据、本版本物资、增幅仪状态 | 部分包明确“本版本”；完整进度可展开查看 |
| 底部 | 当前模式可用操作与快捷键 | 按模式替换；禁用撤销时说明只能重试 |
| 终端面板 | 独立棋盘、规则、时长、当前分 / 目标、结果 | 局部画板与主图不可同时接收输入 |

主色以原作参考的深黑空间、深灰外壳与亮屏功能图标为基准；危险、物资、数据和传送优先使用核对后的原版图标及状态变体。颜色不是唯一编码，必要时增加不遮挡原图的形状 / 文字提示。数据盗取的每种颜色同时绑定字母 / 形状。

UI 正文基线 14 CSS px，主要目标 16 px；正文与背景对比度目标至少 4.5:1。全部菜单可用 Tab / Enter / Esc 操作，焦点可见，退出弹层回到原控制点。游戏动作区获得焦点后再拦截快捷键，不影响用户在设置 / 导入中的常规编辑。

### 2.2 声音与可访问设置

移动、无效动作、拾取、显露、增幅、开门、成功、失败、传送各有短反馈；重复无效移动音效限频，不能与玩法命令互相限速。按 [美术合同](art.md) 优先匹配可用的原版音效，缺失项使用自制 / 合成声音补充；实际采用资源本地打包。

首次“开始 / 继续”手势尝试启用音频；浏览器拒绝时游戏保持可玩并显示启用声音按钮，不弹出阻断主流程的错误。音量默认 0.6，可静音；防火墙始终显示拍点及容错反馈，静音不改变评分。

防火墙音效与判定共享有效时间轴。音频适配器将有效时间映射到 AudioContext 时间，优先使用输出时间戳校准可用映射；不支持时用本次恢复时的性能时钟 / 音频时钟锚点。暂停会取消待播放节点，恢复重新建锚，不播放暂停期间积压的声音。[Web Audio 输出时间戳](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/getOutputTimestamp)

设置提供“减少闪烁”和“减少动态效果”。首次按系统减少动态偏好初始化，之后用户设置优先。减少闪烁关闭 CRT 抖动 / 闪白，不移除拍点边框与危险图案；减少动态关闭镜头平滑 / 震动，仍保留静态状态提示。两种设置不改变地图、时钟和成绩规则。

## 4. 本地存档协议

采用 localStorage 保存小型 JSON 快照，不保存 Three.js 对象、音频时间轴或全量命令日志。一个浏览器来源对应一份进度；协议、主机、端口改变会使用另一存储空间，因此固定入口并提供导出 / 导入。[localStorage 行为](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)

### 4.1 记录与写入

两个交替槽键为 `camellia-golden-week.save.a` / `.b`。每槽是完整 envelope，包含 `saveGeneration, savedAt, payload`；payload 字段见 [数据合同](content.md)。`saveGeneration` 是本地单调递增安全整数，与玩法的 `stateRevision` 分开；新游戏 / 导入也延续本地最大代数，不能让旧槽因代数更大而复活。`savedAt` 只用于展示，不决定哪个槽有效。

恢复外部载荷时，若玩法 `stateRevision >= 2 ** 52`，从 0 建立新的本地玩法修订基线，为后续稳定事务保留至少半个安全整数空间；普通修订号保持原值。该重置不改写导入原文、实际进度或本地 `saveGeneration`，不是存档版本迁移。修订号在恢复后的连续玩法中仍仅随稳定事务递增；具体反例与回归见[消融 Review 修复](../verification/review-fixes.md)。

稳定动作完成后，序列化新快照并完整校验，在持锁状态读取当前最大有效代数，再用一次 `setItem` 写入较旧槽，回读并验证，成功后更新内存中“已保存”的代数。另一个槽保持上一个成功快照；不使用多键指针作为提交依据，不在成功后删旧槽。重复 / 无效行动无写入；实时挑战中不逐帧保存，进入前与结果提交后保存。

单槽序列化 UTF-8 上限 512 KiB，导入文件上限 1 MiB，导入完成后仍须满足单槽上限。内容校验额外生成“全探索 + 全收集 + 最大静态活动房间”快照验证预算，不能等玩家玩到后期才发现超限。浏览器额度或权限仍可能拒绝写入，此时保持内存游戏可玩，状态栏持续显示“未保存，可导出”，手动“重试保存”只写当前快照，不重放奖励事务。

普通稳定快照包括当前位置；静态活动房间包括完整布局 / 重置基线 / 待发结果；迷宫 preview 中加载按完整重置重新观察，active 中加载保持当前位置并隐藏危险；实时未结算恢复到外层安全入口。不要仅依赖关闭页面时的异步保存，卸载事件不保证完成。

### 4.2 多标签页

使用同源 Web Locks 的 `camellia-golden-week.save-writer` 独占锁保护游玩会话。持锁后重新读取最新槽，再允许开始；第二标签页只显示“进度正在另一窗口使用”并可只读导出 / 重试，不抢锁、不合并两个分叉存档。页面离开释放锁，恢复页面须重新获取并重读。浏览器关闭会话后锁由平台释放。[Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)

不支持此 API 或不能取得持久化能力时，提供用户主动选择的“临时游玩，可导出”模式，期间不写已有存档。该降级是为明确的浏览器能力 / 存储拒绝情形设置，不能静默从继续存档切到新游戏。

### 4.3 加载与损坏

先分别解析两槽的公共 envelope，识别最高代数候选，再验证 gameId、版本、结构、引用、位置 / 占格、目标前置和奖励关系。最高候选兼容且有效才自动继续；版本超前与数据损坏按下表分别处理，不能先过滤不兼容槽再静默使用旧档。相同代数但不同载荷属于冲突，停止自动载入并提供两个原始导出。两槽都不存在才显示纯新游戏状态。

| 情况 | 必须行为 |
| --- | --- |
| 最新槽有效，旧槽有效 / 不存在 | 继续最新代数，显示保存时间 |
| 最新槽损坏，旧槽有效 | 显示损坏原因与备份时间，允许预览 / 导出原始槽；用户选择“使用备份继续”后再恢复写入 |
| 两槽损坏 | 不自动新建覆盖；可导出原数据、导入有效文件，或用户明确选择开始新游戏 |
| 最新槽是较新版本 | 提示使用匹配构建；不能只因旧槽兼容就自动回退并覆盖较新进度 |
| 存储不可读 / 写 | 明确显示当前是临时进度，保留内存导出；不假装已保存 |
| 内容引用 / 坐标不合法 | 按版本迁移规则修复；没有对应迁移时拒绝载入，不能把不合法位置随意改成起点再当作正常存档 |

读取失败绝不等同“无档”。保存恢复界面展示普通可读原因，不把内部堆栈当主文案；详情可复制错误码 / 版本用于定位。

### 4.4 导出 / 导入 / 新游戏

导出是带版本信息的完整 JSON；实时挑战中导出安全恢复快照，静态活动中导出当前布局。存储故障时允许直接导出内存数据。导出文件名含项目名和时间，不上传任何服务。

导入顺序：大小和 JSON 解析 → 版本 / 内容校验 → 内存试迁移 → 显示区域、主路径、物资和版本摘要 → 用户选择替换 → 写入一个完整新槽 → 回读确认 → 切换内存世界。任一步失败都不替换现有世界；字符串作为纯数据，不执行文件中的脚本或加载其外部 URL。

已有进度下选择新游戏，需要在游戏内明确确认替换，并提供先导出选项；写入新的完整初始快照，旧槽保留为上一个有效快照。正常继续 / 每次自动保存不要求确认。此处是未来产品操作设计，不是本轮文档写入的审批要求。

## 5. 版本与失败恢复

三类版本分开：`schemaVersion` 为存档结构整数（首版 1）；`contentVersion` 识别完整地图 / 奖励清单；`ruleVersion` 识别可比较的挑战计分规则。发布 profile 不是 schema，也不是“将未收录区域判通关”的开关。

当前防火墙规则 v3：schema 仍为 2，M1–M5 的 contentVersion 分别为 2/3/4/5/5，ruleVersion 统一为 3。旧 v1/v2 内容视图与计分路径保留，`publishedProfileMigrations` 先按同 profile 从 v1 映射到 v2，再升级到 v3，随后只沿 v3 分期升级，保持唯一路径。旧最好成绩按自身规则版本验证并归档，永久结果保留，未完成实时挑战从安全准备态重启；警报接触与闪避游标不持久化。v2 发布历史见[防火墙还原记录](../verification/firewall-restoration.md)，本次依据见 [S12](../references/firewall-hazards.md)，不能把旧记录解释成新谱面。

实施版本记录（2026-09-11）：M1 验收样本使用 schema 1；M2 实施中增加首次成功布局持久化后，当前写入 schema 2。历史 schema 1 的 M1 / M2、rule 1 可明确恢复无推物房间的唯一完成布局：记忆迷宫为空局部布局，一笔画为全部必经格集合。缺少球 / 车 / 盗取实际成功占格的旧载荷不能用标准解补造。结构转换仍先校验、保护原槽并回读备份，再写入，真实浏览器样本与结果见[实施验收](../verification/acceptance-results.md)。

| 变更 | 兼容规则 |
| --- | --- |
| M1 → M2 → M3 → M4 新增区域 / 支路 | 保留已有 ID、已领取集合、首访布局与旧终点历史；新区域采用初始状态；更新分母并提示新增内容 |
| 修正文案 / 贴图 / 音效 | 不改目标与规则版本，不重置进度 |
| 改节拍 / 分值 / 阈值 / 幽灵时序 | 对应 ruleVersion 升级，旧最好成绩归档显示，当前榜从新规则成绩计算；已合法领取奖励及已完成目标保留 |
| 移动格子 / 改房间布局 | contentVersion 升级，提供旧格 ID / 房间状态的具体迁移；无法映射的未完成房间回其安全入口并说明，已完成永久结果保留 |
| 删除或重命名目标 / 奖励 | 必须提供一对一或明确合并映射，验证数额与开门结果；不存在映射时停止迁移 |
| 老构建读取新档 | 不降级猜测、不丢弃未知 ID、不自动覆盖；可导出或用匹配构建打开 |

迁移是旧载荷到新载荷的确定性过程，先在内存完成并校验，再写入。迁移前将两原槽原文保存在单个 `camellia-golden-week.save.pre-migration` 备份键，回读成功才允许写新格式；空间不足则停止持久迁移并提供原始导出。该键只保存最近一次迁移前的数据，后续普通行动不会覆盖它。

兼容新增内容也记录 contentVersion 转换，不能以“schema 相同”跳过语义检查。重复迁移同一存档应得到同一游戏结果，不重复发新增奖励。部分包的结束记录不能转换为 `warehouse.complete`。

回退以静态构建版本为单位，不删除存档；用对应旧备份继续时导入到兼容构建。发现较新存档的旧构建默认保护原槽，即使选择旧备份也只允许临时游玩 / 导出，避免破坏较新版本进度。

## 6. 验证入口与工程成本

开发构建提供 `window.__CAMELLIA_INSPECT__.snapshot()`，只返回深拷贝：profile / 版本、区域 / 格位、mode / phase、有效时间、已完成目标、四区完整 / 本版数据、奖励 ID / 总量、最近结果码、保存状态。不能提供任意设坐标、加分、开门或完成目标的方法。该调试入口不进入正式生产构建；验收 profile 可打开只读观察。

测试使用 Node 原生测试运行器与可注入时钟，类型检查独立执行。[Node 测试运行器](https://nodejs.org/api/test.html) 真实浏览器验收通过正常键鼠进行，自动化可用项目已有浏览器工具，但不是玩家安装前置。

工程命令包括 dev、lint、format、format:check、typecheck、validate:content、test、build、preview；准确行为以 [验收的工程命令合同](acceptance.md#8-未来工程命令合同) 为准。无环境变量、API key、账号、运行时外部 API 或 MCP 依赖。开发安装需要包注册表，运行不需要。锁文件随后续工程提交维护，本轮未安装 / 锁定包，也未启动服务。

增加的恢复机制各对应实际失败面：双槽应对坏档 / 写入失败；迁移备份应对格式升级回退；独占锁应对双窗口覆盖；clockGap 应对后台 / 卡顿；无声和低画质应对浏览器播放 / 图形预算。无需再引入无限重试、云同步或服务端日志系统。
