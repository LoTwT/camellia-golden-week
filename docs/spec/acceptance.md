## 1. 验证分层与证据

| 层 | 方法 | 通过证据 |
| --- | --- | --- |
| 工程静态检查 | Oxlint、Oxfmt 只读格式检查、TypeScript 类型检查；采用 Vue 时覆盖 SFC 与模板类型 | lint 零警告 / 错误，格式一致，类型零错误；记录实际命令与工具版本 |
| 静态内容 | 对每个 profile 校验 schema、引用、目标依赖、账本、谱面和地图边界 | 命令退出 0，列出各 profile 场景 / 数据 / 物资摘要；失败给引用链 |
| 规则 | Node 原生测试、固定初态、正常命令、可注入时间 | 比较权威终态、事件次数与错误码；不得只比较截图 |
| 关卡可解 | 权威规则重放固定命令见证 | 每房成功记录、错误 / 死角恢复记录，含内容 / 规则版本 |
| 浏览器流程 | 正常键鼠完成新档 / 继续 / 回访 / 结算 | 关键画面、只读快照、录屏时间定位或步骤记录 |
| 表现 / 运行 | 指定尺寸 / 浏览器、计时采样、离线与上下文恢复 | 实际设备、软件版本、画质、采样结果、已知未验证项 |

浏览器验收可以使用自动化键鼠；不得通过注入完成目标、直接改位置、加分或打开全部门来通过流程。规则单元测试可以建立合成初态测试边界，但合成初态不能替代全流程验证。各场景坐标在未来地图就绪后录入见证；本规格不编造原图坐标。

每次里程碑提交的验收记录至少包括：构建 / 内容 / 规则版本、profile、执行日期、设备 / 浏览器、命令、结果、关键快照、失败项、来源差异。用“通过 / 失败 / 未验证 / 不再要求”区分；仅用户取消的验收范围可标“不再要求”，未运行的浏览器列不能标通过。不得把 M1 的包内通关作为完整游戏验收。

R1 每项增加来源定位或适配决定、当前实现位置和差异状态；状态明确区分“待核准”“规则已定待实现”“已实现待验证”和“已通过”。待核准项按[主规格 §2.1](overview.md#21-待核准事项的关闭规则)以原证据或明确本版适配关闭；通过时另记“原版一致已证实”或“本版适配已验证”，适配项的原版一致性仍为未验证。未关闭、未实现或未实际验证的用例不得跳过后标为通过。工程检查全绿、旧地图可解或已有 130 存档都不能替代原机制 / 原图对照；历史 62 项通过与 V06 取消的结论保留，不平移成 R1 全量通过。

本次必需环境按[工程合同的当前矩阵](architecture.md#3-浏览器与运行预算)仅验证本机独立 Chrome。用户已接受本机基准的通过结果，并取消真实断外网的发布门槛，依据见[验收范围调整](../verification/acceptance-scope-2026-09-11.md)。原 63 项 ID 和验证层级保留，V06 标为“不再要求”，不计为测试通过；性能阈值不变。Safari / Edge 及其他设备的历史成功、失败与未验证事实保留，不以其他环境结果直接填入 Chrome 或未测设备的实测列。

## 2. 全流程与分期验收

| ID | 起点与动作 | 可观察通过条件 |
| --- | --- | --- |
| G01 | 新档进入中心，完成第一次增幅 | 不出现角色 / 日期 / 战斗前置；获得 1 单位物资，增幅无限使用，A 可进入 |
| G02 | A 只完成路线增幅、迷宫 01、主终端 | A 数据仅 20 / 100 也能开放 B；无须防火墙、迷宫 02 / 03 或回访 |
| G03 | B 只完成一笔画 01、捷径按钮、主终端 | B 数据仅 20 / 100 也能开放 C；杀毒未玩不阻塞 |
| G04 | C 只完成第一组推车捕获与主终端 | 第一组预置推车；三个盗取及后三组捕获均未完成仍能进入 D；C 数据为 20 / 100 |
| G05 | D 以 24 种排列分别取得四权限，暂不取隐藏数据 | 第四个完成时 D 主路径完成，A / B 回访门同时开放；D 数据可停在 80 / 100 |
| G06 | 完成 D 后分别按 A→B、B→A 顺序回访 | 两种顺序均获得两回访数据；无相互前置；先前首访数据和物资不重置 |
| G07 | 继续补 A / B / C / D 的其余必需数据 | 仅在四区各 5 项全齐时开库；任意缺 1 项就保持关闭并指明缺少的区 |
| G08 | 从新档始终不完成防火墙 / 杀毒，走其余必需内容至仓库 | 可完成最终终端；物资低于 130 仍主目标完成，计分挑战显示未完成 |
| G09 | 完整新档全收集并实际完成 C 四组捕获，再多次回访 / 重玩 / 加载 | 26 个奖励 ID、130 单位；各区 30、中心 10；捕获无额外奖励 / 数据；数量不增加；结算事件一次 |
| G10 | M1 / M2 / M3 分别从新档到包内终点，再收全物资 | 各包可独立结束并继续探索，分母为 26 / 51 / 81；未来入口标未收录，不出现必须前往未来区的任务 |
| G11 | M1 A 本版数据全齐后升级至 M4 | 4 个首访数据和 25 A 物资保留；A 完整数据 80 / 100，提示新增回访；未写入完整版通关 |
| G12 | M3 已到包内终点的存档升级 M4，完成剩余内容 | 当前进度可接 D，两个回访 + D + 仓库新增 49 单位；最终最多 130 |

完整通关见证的必需事件顺序：中心教学 → A 主路径 → B 主路径 → C 主路径 → D 四权限 → A / B 回访 → 补齐其余必需数据 → 中央终端。见证可在主路径途中提前补数据；需要至少一条故意推迟 C 三个盗取、A 迷宫 02 / 03 和 D 隐藏数据的记录，证明主路径与开库集合确实分离。

仅做拓扑排序不足以验证可玩性：G02–G09 还要实际经过地图、按机关规则移动并拾取，不可用“触发目标”直接替代行走。

## 3. 公共输入、显露与事务

| ID | 场景 / 操作 | 可观察通过条件 |
| --- | --- | --- |
| I01 | 四向、墙、地图外、两键按住、重复 keydown | 一次一步，无斜行；最近按键生效；无效动作不改世界 / 奖励 / 撤销栈 |
| I02 | 移动动画中快速输入多方向 | 等待方向最多 1 个，新方向覆盖旧方向；不在动画后爆发多步 |
| I03 | 相邻点击、长距离点击、连续切换键鼠 | 共用规则；长距离逐步走，仅经过已访问安全格；遇未知 / 奖励 / 机关停在前一格 |
| I04 | 点击同格对象产生 pointerdown 和 click | 一个手势最多一个事务，奖励 / 分数不双计 |
| I05 | 新游戏移动观察地图，再用增幅仪 | 普通显露不解除以太；R 仅清除明确目标集合，不影响其他富集组 |
| I06 | 对隐藏房间 / 迷宫使用远点击或区域图 | 不显示隐藏答案，不自动走正确迷宫路径；幽灵段不能自动寻路 |
| I07 | 按住方向时打开菜单、切区、失焦后恢复 | 队列为空，松开再按才移动；恢复不多走一步 |
| I08 | 挑战成功帧打断渲染 / 音频，或存储写入失败 | 规则成功一次、事件一次，物资不重算；显示未保存，可导出当前已完成进度 |
| I09 | 往返传送点与区域 30 次 | 落点正确、无反向传送循环；同一世界的机关 / 领取状态保留 |
| I10 | 菜单 / 导入框输入 WASD、R、Z、方向键 | 只作用于当前 UI；画布无穿透点击或误移动 |

## 4. 静态机关

| ID | 场景 / 操作 | 可观察通过条件 |
| --- | --- | --- |
| S01 | 三个迷宫逐图对照，分别观察、成功、踩错、再观察 | 入口 / 危险 / 出口对应原图，第一间核心 8×5；观察隐藏与失败恢复正确，任意合法路径可用；4 秒暂为本版适配，不冒充原实测 |
| S02 | 迷宫中途刷新 / 重置 | 活动态刷新保持位置且答案隐藏；重置回出生并重新观察；无奖励复制 |
| S03 | 两条一笔画逐图核对；重复格、提前终点、死路和撤销 | 按原证据或明确适配冻结的失败 / 终点规则执行；若重复步失败则回起点并清空路径 / 历史，若选择拒绝则保持原状态；尚未关闭时不能通过，适配通过不标原版一致；撤销仍可恢复合法未失败前态 |
| S04 | 三组盗取分别推球、推未组装基站、组合后推增幅器，并尝试进入缓冲区 | 球持续滑行、基站不可单推、组合体一步一格；玩家能绕缓冲区，任何组件不能进入；组合身份 / 占格守恒 |
| S05 | 四组捕获分别先不堵路再封路追赶；测试墙边、串推、越界及后三组推车解锁 | 邦布按已冻结触发 / 逃路规则响应，封路并追上后捕获；不是两球入站；第一组独立、后三组分别由盗取解锁；无效推不部分执行，全部可返回 |
| S06 | 盗取的单球 / 裸基站入接口、异色碰撞、组合体挡另一球、所有必需接口完成 | 单组件不冒充组合体；匹配和可解性按当前布局计算，组合后才能满足接口；拆分 / 退出接口按已冻结规则；存在合法替代解时必须接受 |
| S07 | 捕获和盗取走入死角，在组合前后 / 捕获前连续撤销、超过 256 步、重置 | 玩家、球 / 基站身份、组合体、推车、邦布及局部状态完整恢复；不复制推车或奖励；历史尽头明确，重置仍可用 |
| S08 | 静态房间中途退出 / 刷新 / 放弃后重入 | 刷新可续布局；放弃回安全外层入口；临时结果不泄露到全局 |
| S09 | 成功后试图撤销领奖，再进入练习；对仅有旧归档的房间首次完成新版练习 | 不能撤销全局提交；练习不关闭永久门、不丢权限、不重复提交目标 / 奖励；仅在当前兼容布局缺席时补存实际首份成功布局，重复练习不覆盖它或旧归档 |

存在多解的内容至少使用两条不同路径测试；唯一解房间必须明确为唯一解，不能为了满足数量编造替代解。规则实现应允许多解，内容见证不作为答案白名单。

## 5. 实时与时间边界

下面的时间均为本版有效时间 / 合成测试时间，不是原作录屏测量。

| ID | 场景 / 操作 | 可观察通过条件 |
| --- | --- | --- |
| T01 | 当前防火墙第一拍 `30000÷110 ms`，在首拍前后各 150ms 作无警报接触的有效移动 | 两端点均命中，分别向窗外再移 1ms 为错拍；独立初态避免同拍重复干扰；v1 的 250 / 100 / 400ms 记录保留历史含义 |
| T02 | 同一拍多次点击、长按键、点击当前格，普通错拍与警报受击 | 同拍最多 +1且不能刷新闪避；长按不自动计拍；当前格不加分；v3 普通错拍 −1、警报 −5，最低 0，最高值保留；旧版规则仍按各自版本验证 |
| T03 | 迎向 / 横向 / 背向跨警报、驻留、闪避到期、持续接触及同刻输入 | v3 正确来向踩拍可闪避；无保护接触扣 5，持续同一接触不按帧重复扣；离开重入和新警报可再扣；批量与分帧、同刻 Tick 后输入、重试均一致；精确时序为重建 |
| T04 | 防火墙分别达到 12 / 40 / 55 / 70 最高 Combo，再等待结束 | 对应档位成功；未达标失败；v3 教学最多 27、正式最多 82；奖励门只首次开启；v1 的 30 / 90 及 v2 的 27 / 82 成绩可按原规则升级归档 |
| T05 | 杀毒逐档验证出现 / 有依据的过期、完全不清理、数量到上限 / 超限及同刻清除 | 未清数据确实积累；所示原模式的 9 个上限有来源，逐档按已冻结条件处理超限；不能靠全体短 TTL 消除压力；同刻顺序与分帧 / 批量一致 |
| T06 | 星星与普通点击同时间命中同一数据；重复点已清 / 已消失 ID | 同一实例只计一次，剩余数量同步减少；作用范围、星本体计分和是否连锁按逐档已冻结规则，不清未来实例 |
| T07 | 防火墙截止与杀毒已冻结的截止 / 超限结束，分别在边界前 1ms 及同刻输入 | 防火墙保持当前边界；杀毒按已冻结结束优先级处理，结果不受面板延迟影响，结束后不再计分或发奖 |
| T08 | 运行中静音、调音量、关闭闪烁 | 相同命令 / 时间得到同分；视觉拍点与危险语义仍可辨 |
| T09 | 幽灵走入静止玩家、玩家与幽灵交换格、双方跟随 | 前两者失败，最后一种在无最终同格 / 交换时存活；不同帧率一致 |
| T10 | 在同一时刻走入有幽灵的灯格；随后测试正常亮灯 | 碰撞优先，失败不点亮；存活点亮仅清指定组；失败恢复初始灯 / 幽灵 |
| T11 | 在幽灵首次移动前 1ms 暂停，切后台 30 秒，再恢复 | 仍剩 1ms 到首步；3 秒恢复倒数不计入；恢复前不移动；无补跑 60 步 |
| T12 | 人为让前台调度中断 300ms | 冻结到最后已处理时间，进入 clockGap 提示；不补算输入，不直接判失败 |
| T13 | 同一实时见证在模拟 30 / 60 / 120fps 下重放 | 得到相同玩家 / 对象终态、分数、成功结果及事件次数 |
| T14 | 三档杀毒在已冻结生成 / 生命周期下，用正常键鼠完成成功、堆积失败及星清场 | 至少 150ms 反应时间下可成功；失败后可重试；数量、侧屏和判定一致；旧 45 秒 TTL 见证及理论总分不足以通过 |

## 6. 存档、升级与故障

| ID | 注入条件 / 操作 | 可观察通过条件 |
| --- | --- | --- |
| P01 | 各区域普通行动后刷新，静态房间中途刷新 | 回到最后成功保存的稳定状态；物体 / 访问路径一致；历史撤销为空但重置可用 |
| P02 | 实时挑战中刷新、成功事务后动画前刷新 | 前者回安全入口重开；后者保留已提交完成 / 奖励，不强制重打 |
| P03 | 写新槽之前失败、setItem 抛错、新槽写后回读不匹配 / 抛错 / 校验失败，再重试或加载 | 写前失败不动两槽；写后失败保留另一上一有效槽和已验证的迁移备份，不要求目标槽原文不变；普通内存结果不回滚 / 重复，导入 / 迁移不切换候选世界；不显示已保存，重试前重读实际槽 |
| P04 | 最新槽为坏 JSON、两槽都坏、两槽代数逆序 | 明确区分损坏 / 无档；按有效代数选择；不按写入键名或系统时间猜测 |
| P05 | 最新槽为较新 schema / content，旧槽可读 | 不静默选旧槽继续写；较新进度受保护，可导出 |
| P06 | 导入超限、错误项目、未知目标、非法占格、脚本字符串 | 校验失败且旧世界不变；数据不执行；合法导入预览后才替换 |
| P07 | M1→M2→M3→M4 及直接 M1→M4，重复运行迁移 | 已完成 / 领取稳定，新增默认状态一致，无额外物资；迁移前原槽备份可读 |
| P08 | R1 规则 / 地图升级：旧 A / B 布局、旧 C 球关与同色盗取、旧杀毒成绩、无映射奖励；旧 completedVisit 迁移后重入、新版实际成功再刷新 | 原完成 / 领取 / 通行保留；新捕获不伪造已体验；活动尝试与完成回访均按映射续玩或回安全入口；归档不能补造新解，当前布局缺席时不误入 completedVisit；实际成功才补存新版首份布局，刷新 / 重玩不覆盖；无安全映射 / 备份则停止迁移 |
| P09 | localStorage 被禁止 / 额度不足、迁移备份写不下或备份回读不匹配 / 抛错 | 显示未保存 / 停止持久迁移；尚未写新槽，两原槽不覆盖；可导出当前 / 原始数据；新槽写后故障按 P03 验证 |
| P10 | 同源同时打开两标签、持锁标签关闭 / 页面恢复 | 只一个可写游戏；另一个不抢锁；获得锁后重读，不写入过期快照 |
| P11 | 新游戏 / 导入后再加载 | 代数不倒退，不复活旧槽；前一次有效快照可作为显式恢复来源 |
| P12 | 改系统日期、改本地端口 | 日期不改变最新槽 / 挑战；不同端口提示存储来源说明，可导入迁移；默认服务不换端口 |

P08 至少包含旧盗取 `completedVisit` 的连续链：使用真实旧档迁移，确认无兼容映射时回安全外层入口、通行及未领物资格保留；普通重入不展示旧棋盘或伪造的新成功图，正常键鼠进入新版练习。中途刷新 / 放弃仍只有旧归档，实际成功后新增当前布局，再刷新及重玩，首份布局 / 旧归档 / 永久目标与奖励均保持；有合法替代解时用替代解重玩，唯一解则重放原合法解，不编造多解。另以对应夹具验证兼容映射可续访、无安全入口 / 出口映射拒绝，以及“永久已完成但无当前布局也无合法归档”的坏档拒绝；不以这些夹具替代正常游玩链。

## 8. 未来工程命令合同

下列工程入口在 M1–M5 实施中建立；后续按用户要求统一改为 pnpm，本轮结果见[pnpm 迁移记录](../verification/pnpm-migration.md)，当前说明见 [README](../../README.md#工程检查)，原始日志见[验收结果](../verification/acceptance-results.md)。最初规格交付时尚无 package.json 的状态属于历史记录。

工作目录是当前 `camellia-golden-week` 仓库，不新建旁支应用目录。

| 命令 | 行为与通过标准 |
| --- | --- |
| `pnpm install --frozen-lockfile` | 严格按已提交 pnpm-lock.yaml 安装；缺失或不匹配时失败，不在验收安装中重写锁文件 |
| `pnpm run dev --host localhost --port 5174 --strictPort` | 单个本地开发服务，端口占用时报错 |
| `pnpm run lint` | 执行 `oxlint --deny-warnings`，只检查，不自动修改；源码、脚本与测试零警告 / 错误 |
| `pnpm run format` | 执行 `oxfmt`，按项目配置写入支持文件的格式变更 |
| `pnpm run format:check` | 执行 `oxfmt --check`，只检查，不写入；格式不一致时非零退出 |
| `pnpm run typecheck` | tsc 无输出类型检查，含源代码、校验脚本与测试，零错误；采用 Vue 时增加 `vue-tsc --noEmit` 覆盖 SFC 与模板类型 |
| `pnpm run validate:content` | 执行 TypeScript 内容校验脚本，逐 profile 检查并重放关卡见证 |
| `pnpm test` | 递归发现 tests/ 下的 .test.ts，由 Node 原生测试运行器执行；没有实际执行的用例、失败或发现过程异常均返回非零 |
| `pnpm run validate:architecture` | 只读检查真实 TypeScript 依赖与符号；核心层只引用 core 内模块，不依赖浏览器或平台 API |
| `pnpm run build` | lint、格式检查、类型检查、架构与内容校验通过后执行 Vite build，产出完整静态 dist；构建过程不自动修复或格式化源码 |
| `pnpm run validate:artifacts` | 只读检查实际 dist 的 M5 profile、对应资源 / 哈希与生产验收入口隔离 |
| `pnpm run test:browser` | 独立 Chrome context / 临时端口运行五个分期静态包的正常键鼠与保存恢复，并运行具名异常输入 / 存储 / 音频回归；不修改日常浏览器进度 |
| `pnpm run verify` | 串联原生测试、完整 build、dist 检查和 Chrome 回归；任一失败均不能作为完整验证通过 |
| `pnpm run preview --host localhost --port 5174 --strictPort` | 关闭 dev 后使用同一来源验证静态构建与存档 |

不要求玩家安装测试工具、MCP 或浏览器插件。每里程碑先跑必要的 lint / 格式 / 类型 / 内容 / 规则检查，再跑该阶段新增流程与受影响的升级路径；只有代码变更、失败或未关闭风险才重复扩大全套测试。

## 9. 完成定义

M1–M3 完成意味着包内终点与全部收录内容可达、保存恢复可用，且未收录内容不会阻塞。M4 完成意味着完整新档 / 升级档可开库，130 收集账本闭合，所有必需机关可解可恢复。M5 完成还要求工程合同当前的 Chrome 浏览器矩阵、六类画面、性能与来源差异有实测记录。

R1 完成另须：S13 所列已确认差异完成实现，待核准项已按主规格 §2.1 关闭，原版一致与本版适配分别列明，四组捕获和三组盗取正常游玩、杀毒堆积与失败、地图 / 视听对照及旧档迁移均有新版本证据。关闭路径不豁免必需验证，也不改变 V06 不再要求的状态。只更新本合同不改变旧成品的验证状态，也不表示新增要求通过。

**规格交付**完成意味着：文档索引与各份合同导航完整；范围与旧计划取舍明确；所有推进条件、数据 / 物资分母、失败 / 恢复和阶段终点有唯一合同；未知原图信息有负责人、补证时点和重建规则。它不表示游戏的 G / I / S / T / P / V 用例已通过。
