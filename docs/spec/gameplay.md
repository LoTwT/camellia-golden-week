## 1. 棋盘、可见性与占格

每张地图使用整数 `(x, y)`；x 向右、y 向下。仅四向相邻，无斜走、跳格或拉物体。空缺坐标视为地图外，不能用矩形宽高补出可走格。地形与实体分开：一个格子可同时有地板、电源接口、可移动组件；至多一个独立阻挡实体。数据盗取另有玩家可通行、组件不可进入的缓冲地形；组合后的球和基站是一个占格实体，不能按两个独立物体重叠处理。

中心和主地图移动规则相同。主地图的房间以显式边界划分；房间不是独立菜单关卡，进入 / 离开仍从地图上的入口 / 出口发生。终端小游戏使用独立局部棋盘，保存外层入口位置。

| 格子状态 | 表现 | 可操作性 |
| --- | --- | --- |
| 未发现 | 黑暗背景或无内容的电视轮廓，不展示图标 | 不能远程寻路或点出隐藏内容 |
| 已发现、以太覆盖 | 可辨识覆盖边框，内容图标隐藏 | 不可走入，等待对应富集节点清除 |
| 已发现、清除、未访问 | 展示已知地形和对象 | 手动相邻移动；自动寻路不穿过未访问格 |
| 已访问安全格 | 正常屏幕 | 满足安全条件时可用于自动行走 |
| 隐藏路径 | 初始不可见 | 仅由指定观察点 / 增幅仪 / 按钮揭示，不能靠射线拾取泄露 |

进入普通格后显露当前格及其四个相邻格，不向第二圈传播，也不穿透显式隐藏组。显露以太覆盖格不等于驱散覆盖；增幅仪清除覆盖不自动“访问”它们。发现记录通常永久保留；迷宫的危险分布只在观察阶段显示，不写入普通地图图例。

## 2. 输入合同

画布获得游戏焦点时消费游戏按键，方向键不滚动网页；输入框、菜单按钮和导入对话框获得焦点时不发送移动命令。所有功能都有中文文字按钮或明确图标提示，键盘和鼠标经过同一合法性判断。

| 输入 | 普通探索 / 静态解谜 | 特殊模式 |
| --- | --- | --- |
| WASD / 方向键 | 四方向一步一格 | 防火墙为单次按键移动；杀毒 / 幽灵可长按移动 |
| 点击相邻格 | 一次相邻移动或推物尝试 | 各挑战按下文覆盖 |
| 点击远格 | 仅普通探索可发起已访问安全路径 | 静态谜题 / 幽灵只接受相邻点击；防火墙 / 杀毒允许局部棋盘直接跳到目标 |
| F / 交互按钮 | 当前格终端、开关、观察点、挑战入口；当前格无对象时提示 | 杀毒可清除光标所在格目标；其他实时挑战不复用 F |
| R / 增幅按钮 | 玩家站在有效富集节点上使用 | 所有挑战内禁用 |
| Z / 撤销 | 仅静态房间的活动阶段 | 实时模式禁用 |
| 重置房间 | 静态房间入口布局重开 | 实时模式为重新挑战 |
| M / 区域图 | 只显示已发现地图及已激活传送点 | 挑战中仅提供暂停菜单，不允许通过传送逃避局部结算 |
| Esc / 暂停 | 设置、保存退出、返回入口 | 实时模式冻结有效时间；恢复需显式操作 |

普通移动动画上限 140ms；当前表现目标为 90ms，给输入处理和帧呈现留出余量，实测见[R1性能记录](../verification/r1-visual-performance.md#普通世界端点修复后通过失败保留)。普通输入间隔仍为 140ms。长按由输入适配器自行处理：首次重复等待 250ms，此后每 140ms 尝试一次，忽略浏览器自身 `keydown.repeat`。同一时刻按多方向时只使用最近按下且仍按住的方向；松开后回到前一个仍按住的方向，不能生成斜向命令。

普通探索 / 静态模式最多保留 1 个等待方向；新方向替换旧方向。动画只约束显示与接受下一操作的节奏，不决定成功事件。无效移动不入撤销栈、不存档、不积累补偿步数。模式切换、暂停、失焦、地图传送、失败、重置、导入和加载时清空按键及命令队列，恢复要求松开后重新按下。

鼠标按 `pointerdown` 只生成一个动作，不再对同一手势的 `click` 生成第二个动作。菜单覆盖时禁止画布命中；点击过期对象按无目标处理。防火墙与杀毒的局部直接点击例外须在入场说明中写明，不能外溢为主地图瞬移。

### 2.1 自动行走

仅在 `explore` 中执行最短安全路径；等长路线按上、右、下、左选取，保持重放一致。候选格必须已访问、已发现、无覆盖、可通行，且不存在未领取奖励、交互对象、危险、挑战入口、推物或传送出口。只走普通地板及已打开且无其他事件的门。

路径逐步重新校验，不能一次提交最终坐标。新键盘方向 / 新点击取消旧路径；遇见边界变化、模式入口或未清理事件时停在其前一个安全格，由玩家继续操作。不跨地图寻路，不利用隐藏地形计算路径，不自动求解静态谜题。

## 3. 单次行动与事务

规则层接收命令、内容和权威状态，返回新状态、结果码与反馈事件。顺序固定如下：

1. 检查模式、暂停、输入对象、边界、已知权限和占格。无效返回具体原因，不能部分修改布局。
2. 求本次位移及推物完整落点；所有受影响对象一起检查。长距离滑球是一次原子动作。
3. 暂存位置 / 局部状态，做该模式的危险与失败判定。失败直接转入房间恢复，不执行该动作的拾取和成功事件。
4. 执行当前格的自动事件：普通数据 / 物资拾取、首次到达传送点、房间内灯。需 F / R 的终端不在踩踏时隐式激活。
5. 更新显露、解谜完成条件、目标结果；计算派生区域进度、下一区开放、回访门及仓库门。
6. 若是未完成静态房间，保留临时结果；若到达房间成功条件，整包提交其目标、奖励、门及完成布局。普通探索的拾取直接全局提交。
7. 递增权威修订号，生成不可重复的反馈事件，发出稳定快照；渲染 / 声音订阅结果。保存失败只影响持久化状态，不把成功判定重做一次。

一次操作最多跨一个场景或进入一个挑战；传送落点不得立即触发反向传送，须先离开再重入 / 交互。内容不允许无限链式传送或递归触发器。所有永久门为开启后锁存；需要反复变化的物体 / 门只能存在于房间局部状态中。

同一成功事务既完成目标又登记已领取奖励；外层 UI 不再执行“发奖励”。拿过的奖励 ID 再触发时返回“已领取”，总量始终从 ID 集合求和。读取旧快照会整体回到旧世界和旧领取集合，不在旧总数上再次累加。

## 4. 状态与时间

| 运行模式 | 允许的推进 | 时间规则 | 正常退出 |
| --- | --- | --- | --- |
| `explore` | 普通地图行动 | 不随等待变化，无总倒计时 | 入口 / 终端 / 传送 / 菜单 |
| `staticPuzzle`，`preview` 阶段 | 记忆迷宫观察，禁止移动 | 观察有效时间 4,000ms | 自动转 `active`，或菜单退出 |
| `staticPuzzle`，`active` 阶段 | 迷宫、一笔画、捕获、数据盗取 | 每次合法行动更新，无墙钟消耗；捕获反应与玩家行动同事务 | 成功、重置、放弃 |
| `challengeReady` | 说明、难度选择 | 尚未启动时钟 | 点击开始后 3 秒准备倒数 |
| `challengeRunning` | 防火墙 / 杀毒 / 幽灵 | 专用有效时钟 | 成功、到时、碰撞、放弃 |
| `challengeResult` | 结果、重试、返回 | 停止 | 重试入准备态，返回外层入口 |
| `transition` | 已提交的区域切换动画 | 不接受玩法输入 | 新场景显示完毕回探索 |

暂停是覆盖在当前模式上的状态，有 `manual / hidden / blur / clockGap / graphicsLost` 原因集合。存在任一原因时不处理玩法命令；自动暂停同时设置等待玩家恢复的标记。窗口重新可见 / 获得焦点只移除相应系统原因，仍展示“继续”，不会自行开始计时。只有页面可见、画布已可操作且图形可用时，Resume 才清除等待标记及 manual / clockGap；尚未消失的系统原因不能被强制清除。静态模式恢复立即可操作；实时模式恢复有 3 秒提示倒数，倒数不计入挑战时间；迷宫观察按剩余观察时间恢复。

### 4.1 有效时钟

运行时以单调性能时钟计毫秒，扣除暂停与准备倒数；不使用系统日期、帧数或 `setInterval` 调用次数。实时事件按有效时间处理；测试注入同一时间源。浏览器后台会节流或暂停动画回调，因此须显式处理可见性变化。[性能时钟](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)、[页面可见性](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)

输入适配器在事件处理入口记录单调时间与递增序号。推进到时间 t 时，先处理 t 之前的全部计划事件，再按下文规则处理 t 的事件。同一时间多输入按序号；一个事件不能因多次渲染重复执行。

连续两次前台调度间隔超过 250ms 时，在推进之前进入 `clockGap` 暂停，冻结到最后已处理时刻，清空该间隔的新输入；不追补大量幽灵步数或判为错拍。暂停与卡顿不扣奖励，不把恢复倒数视为游戏时间。帧率正常但低于目标时仍按时间表运行。

防火墙有效区间为 `[0, durationMs)`，到截止时刻先结束挑战，再处理同刻输入。杀毒的生命周期、数量超限、同刻清除与截止结算顺序须按 §7.2 的逐档规则表冻结；旧版“目标过期 → 新目标出现 → 输入 → 成绩派生”只用于旧规则重放，不能先自动清空数据以绕过数量检查。幽灵采用其专用同步碰撞规则。静态关卡没有超时。

### 4.2 失败、放弃、撤销和重放

每个房间定义安全外层入口、内部出生点、重置布局、成功出口。入口不能是危险格或自动触发回跳的传送格。失败 / 放弃丢弃本次临时数据，保留之前全局进度，无生命 / 货币损失。

静态活动阶段的每次合法动作留下完整前态，包含玩家、物体、已走路径、局部灯 / 机关和待发结果；最多保留最近 256 步。没有撤销历史时显示不可撤销，仍能重置。撤销不倒退其他房间已提交的永久状态；成功是边界，提交后清空历史，不能撤销领奖。刷新后恢复布局但不恢复撤销历史，提示可重置。

房间重置回本次入口基线，记忆迷宫重新观察；放弃回外层入口。静态房间成功后将玩家置于安全成功出口，退出 active 模式；具有当前兼容完成布局的房间保持可通行的完成布局，迷宫危险 / 一笔画重复访问限制不再作用，推物停在成功布局且不接受新的推动。旧永久目标已完成但缺少当前兼容布局时，按[版本化完成布局与回访](content.md#51-版本化完成布局与回访)保留通行、从初态重新体验；实际成功可补存当前版本的首份布局，不能覆盖已有首份布局或旧归档。重新挑战不再提交已取得的目标或奖励，不会关闭永久门或撤回权限。实时挑战每次从零开始，本轮中间 Combo / 分数 / 幽灵灯态不持久化。

## 6. A 区：记忆迷宫与防火墙

### 6.1 记忆迷宫

固定内容为 `a.maze.01 / 02 / 03`。01 位于主路径，02 / 03 属开库数据支路。进入后展示安全 / 危险格分布 4 秒，随后隐藏危险图标；布局不随机，不限尝试次数。初次说明只解释目标，不提前展示解答序列。

R1 三图已分别按原截图测绘为 8 列 × 5 行核心，另含左侧 `(-1,2)` 入口；三图危险分布、出口和原图定位分别见[地图冻结 §5](../references/r1-map-mechanism-evidence.md#5-a-三迷宫测绘和观察适配)，不能由第一图尺寸推测其余图或保留旧图。所有核心格均可踏入，危险格不是墙。采纳 **A-R1-OBSERVATION-4000**：完整观察 4,000ms，观察中不接受移动；失败 / 重置重新观察完整4秒，暂停按剩余有效时间恢复。这些观察边界是已冻结的本版适配，原版精确时长与观察期输入仍未证实。

玩家以相邻移动到出口即成功；危险格触发失败，本次所有暂存结果丢弃，回内部出生点重新观察。墙 / 地图外属于无效动作，不算踩错。再次观察等价于重置尝试，不允许站在迷宫中段随时显示答案；不存在根据点击目标自动算出安全路径的功能。

成功按实际地形与出口判定；允许任何合法路线，不比较预录按键串。每房至少提供一条通关见证，01 在不取得任何后期能力时可解。见证用于校验，不能成为运行时答案判定。

### 6.2 突破防火墙

外层终端进入局部 **5 × 4** 方格，光标从中间位置 `(2,2)` 开始。2026-09-11 按用户要求核对原版后采用该构图，并增加左右四块 COMBO 电视。110 BPM 来自三首原曲公开试听的实测；精确游戏谱面、首拍和判定窗仍为重建参数，依据与边界见 [S11](../references/firewall-audio.md)。方向键只能相邻移动，鼠标可直接选择局部任意不同格；点当前格 / 越界不移动也不计分。禁止按住键自动产生节拍输入，每次物理按下只判一次。

| 档位 | 有效时长 | BPM / 拍间隔 | 拍数 | 通过所需最高 Combo |
| --- | --- | --- | --- | --- |
| 教学 | 15 秒 | 110 / 60000÷110 ms | 27 | 12 |
| 内层 | 45 秒 | 110 / 60000÷110 ms | 82 | 40 |
| 深层 | 45 秒 | 110 / 60000÷110 ms | 82 | 55 |
| 核心 | 45 秒 | 110 / 60000÷110 ms | 82 | 70 |

拍点从半拍 `30000÷110 ms`（约 272.727ms）开始，每隔一拍（约 545.455ms），最后一拍约为 14,454.545 / 44,454.545ms；判定窗为拍点前后各 150ms，两个端点计入有效。计算保留完整精度，不逐拍四舍五入。窗口互不重叠，第一拍和最后一拍的完整窗口均落在挑战内。教学完成开放正式档位访问；三档之间可自由选择。

配乐、周边白光、底部“现在移动 / 本拍命中”文字和成绩读取同一有效时间；成功命中时侧屏短暂显示 PERFECT，错拍有效移动显示 MISS。暂停和失焦停止配乐，恢复倒数结束后从冻结的乐句位置续播。三首随包配乐为 110 BPM / 32 拍原创替代循环，不包含原曲录音。减少闪烁关闭白光及亮暗变化，保留固定底色的文字和危险格符号；静音仍可完整跟拍。

2026-09-12 规则 v3 根据 [S12 原版手册与逐帧录像](../references/firewall-hazards.md)修正扣分和闪避。一次移动只匹配最近拍点；每拍首次有效移动在未受击时当前 Combo 加 1。普通错拍减 1，警报受击减 5，最低均为 0；两者不清除历史最高值。没有移动时不因漏拍扣分，但移动警报仍可触碰驻留玩家。Combo 是可扣减计数，不是严格连续命中数。

v3 使用固定 `alarms` 排表，每条警报有稳定 ID、开始 / 结束时刻、来向及逐格移动时间表。危险与预告都从同一排表投影；新覆盖的格子提前 150ms 预告，箭头表示应迎向的来处。警报在拍点后 100ms 换格。首次踩拍移动开启有限闪避，终点为 `max(输入时间, 匹配拍点) + 150ms`：早侧有效输入能覆盖警报换格，晚侧至少保留输入后 150ms。仅相同来向受到保护，实际成功躲过接触才显示“完美闪避”。窗口结束仍接触警报会受击。横向或背向移动不能凭前一次闪避借用保护，同拍再次移动不能重新加分或刷新窗口。

同一警报连续接触只扣一次，离开后再进入或接触另一条警报可再次受击；同刻多个新警报接触合并一次扣 5。新碰撞优先于该输入的普通拍点判定，因此该次不另加 1 或再减 1；若该次有效输入原本匹配拍点，该拍仍记为已判，不能重复输入补分。单独由时间推进产生的被动受击不消耗尚未输入的拍点，随后窗内首次有效移动仍可按正常规则得分。同刻警报变化与输入统一结算，单独推进到精确边界保留该刻输入机会，跨过边界时完成结算；截止时不再受理输入。这些 100 / 150ms、持续接触去重与优先级是明确的本版重建，不宣称来自原游戏源码。固定谱面须有正常方向键可解见证，重试排表一致，无额外墙。

最高 Combo 随当前值更新，到时按最高值判定成功；达标后可继续提高成绩，不重复发奖励。教学不发物资，正式三档各解锁一个 5 单位物资格。计分挑战不提供开库数据。每拍最多 +1 的设计上限是 27 / 82，所有阈值必须低于该上限并有真实时间操作记录。v1 的 5×5 / 120 BPM / 30或90拍及 v2 的掩码 / 旧扣分保留在各自历史内容源与规则路径中。v3 归档旧成绩，已完成目标、合法奖励和主线进度保留。原版核心约 70 秒 / 60 目标的已知差异单列于 S12，本次没有调整上表门槛。

### 8.2 数据盗取 `c.theft.01 / 02 / 03`

R1 实施冻结（2026-09-12）：采纳 [C-R1-COMPONENT-BOUNDARIES](../references/r1-map-mechanism-evidence.md#22-具名本版适配c-r1-component-boundaries) 的完整交互边界。该记录区分原手册 / 视频确认的机制与未见输入的本版适配，含组装后停止、异色阻挡、组件守恒、全部配对后接口激活、接口进出及撤销 / 重置。三关布局由同页视频转录，未核完的坐标不进入运行内容。决定已定，实际实现与验收另记，不将适配称原版已证实。

| 对象 / 地形 | 原规则目标 |
| --- | --- |
| 信号球 | 推动后沿对应方向持续滑行；路径阻挡、匹配基站或边界决定停点，玩家只进入球的原格 |
| 未组装基站 | 不可独立推动；与匹配信号球组合，形成一个组合增幅器 |
| 组合增幅器 | 每次推动恰好移动 1 格；保留球与基站组成关系，可用于阻挡另一球的滑行路径 |
| 电源接口 | 坐标预定义，全部必需球 / 站配对前隐藏且不激活、所在位置为普通地板；全部配对后统一显示 / 激活并立即按占格判满足，只有匹配组合体可满足 |

### 9.1 幽灵段

每段为局部实时房间，有安全内部出生点、明确出口、灯分组与幽灵固定路径。进入说明后主动开始；前 3 秒准备倒数显示全部可见危险位置。没有总超时或追逐 AI。

R1 两房分别使用 S05-50 / S05-30 的5×5核心形态及外接入口 / 出口。D01有六砖墙，D02有三处无格，两者不能混画；坐标、灯与幽灵初态见[地图冻结 §7](../references/r1-map-mechanism-evidence.md#7-d-幽灵灯与四权限)。采纳 **D-R1-PATROL-500** 的路径、500ms幽灵步频、140ms玩家间隔、灯范围与同步碰撞边界。原图支持“碰撞回起点、亮灯驱散”，未见的速度、灯范围等已以本版适配关闭，不能称原版精确参数。每房正常见证须实际包含路线选择、等待避让与亮灯；纯规则证明不替代真实浏览器验收。

幽灵每 500ms 沿有序路径前进 1 格，路径只能四向连续；采用首尾也相邻的循环路线，首步在有效时间 500ms，初始相位为路径第 0 格。不同幽灵使用各自路径，房间数据不允许它们在同刻重合或交换；不存在随机速度。玩家移动的最短间隔为 140ms，与普通长按节奏一致，不由幽灵步频决定。

当玩家与幽灵事件同刻发生，先计算双方的移动意图，再统一检查：最终同格，或双方在此时交换原格，均为碰撞；幽灵走入静止玩家也碰撞。仅仅同时跟随离开同一格、且无同格或交换，不碰撞。连续输入同刻最多处理一个玩家移动，多余移动丢弃。

碰撞判定优先于同刻灯的触发；存活后踏入灯格即自动点亮，移除其 `ghostIds` 内的幽灵，其他组保持不变。不能利用同刻亮灯穿过幽灵。灯效果只在本次尝试中有效，碰撞 / 重试恢复所有初始幽灵和灯。

达到段出口即成功，不增加全部灯已亮前置；存在绕灯合法解时保留并另记。提交该段完成状态，使其后普通回访成为安全通路；需要重复挑战时进入练习实例。权限 / 永久物资放在段出口安全侧，不能在危险段中边领永久奖励边重置。碰撞回内部入口并显示重试 / 返回，重试前时钟保持停止。
